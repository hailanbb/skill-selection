## 点哪里，什么时候真正下载

1. 登录 MoviePilot，确认站点、默认下载器及自动保存目录已经正常配置。
2. 点击“导入 Excel”，选择第一脚本导出或人工维护的 `.xlsx`，最大 30 MB。导入只排队；看到“尚未执行”是正常的。
3. 查看非绿色项数量、跳过项及错误信息。修正源链接、季号或来源数量不明的行后再重新导入。
4. 点击 **“开始补缺下载”**。此时才开始查找资源、检查现有任务并提交下载，不会再逐资源弹窗确认。
5. 需要停下时点“暂停”，当前已发出的请求会先记录结果。点“继续本轮”才继续。
6. 完成或暂停后点击“导出更新报告”，另存为 `_下载补充.xlsx`。刷新前先导出；原文件不会被覆盖。

下载使用 MoviePilot 的默认下载器与自动目录，不创建订阅、不修改下载器设置，也不直接写云盘文件。脚本所需的 `MoviePilotAPI` 由页面提供，身份认证沿用页面，不需要在脚本里填写登录令牌。

## 哪些行会进入任务

- 跳过“剧集目录”格为绿色、归档紫色或文字标明已归档的行。蓝色、红色、无填色和旧黄色行会检查；有下载记录时仍防重复。
- 必须有有效来源登记集数；没有已确认缺集时不下载。重复版本或状态待核实，不等于需要重新下载。
- 路径、分类、剧名、季号和源链接必须相互对应。第二脚本的 CLOUD 与 SOURCE 必须和第一脚本一致。
- 待播及播期未知的集目不下载。缺集范围未知时，只允许明确完整包，不猜零散集号。
- 条件格式、合并目录格、身份/来源字段公式或重复关键表头会拒绝处理，保留并提示原因。

## 如何选资源

先确认媒体身份：报告中的 TMDB ID 优先，其次豆瓣 ID，均无时才用完整标题/原名与年份。名称统一简繁、全半角和不可见字符，不把任意译名或前缀相似认成同剧。明确冲突 ID 不会被同名结果覆盖；同名同年多个媒体 ID 时暂缓。

每个资源还需确认电视剧类型、**当前单季**、明确覆盖集号、有效下载入口及至少 2 个做种。混季、错误季、集号冲突、做种未知不自动选择。只有 `S01` 不代表整季；需明确集号覆盖，或“全 N 集”与来源数量一致。

### 优先级从上到下

1. **完整季包优先**。没有合格整季包时才使用零散单集或多集资源。已有成功提交的集目时不再改下整季包。
2. **同类优先中文标记**。支持中文、中文字幕、中字、简中、繁体字幕、国语、国配、CHS/CHT 等明确标签，也读标题/副标题中的明确字幕或配音说明。中文片名不代表有字幕；“无中文字幕”“No Chinese subtitles”等否定或冲突标记不提升优先级。标记来自站点声明，不是实际媒体验证。
3. **同等中文条件下优先≥5个做种的候选**。5 个算达到阈值；2—4 个做种的资源不会仅因更小抢占这一组。
4. **这一组容量全部已知时优先小容量**。整季比较总容量；零散多集比较 `总容量 ÷ 本次能补上的缺失集数`。选完一个资源后，重新计算剩余缺集与成本；容量相同再看做种数。
5. **没有≥5候选，或高做种组存在未知容量时，按做种数从多到少**。未知大小不是零。仍同分时采用稳定排序，避免仅因接口返回顺序变化而改变结果。

例如，同样带中字标签的两个整季包：A 为 50 做种 / 30 GB，B 为 5 做种 / 10 GB，优先 B。若 B 只有 4 做种，优先 A。同类中有 2 做种的明确中文资源、另一资源无中文标记且 100 做种时，中文资源优先；没有中文资源时仍可选择其他合格资源。

零散集的容量是成本估算：1.2 GB 的双集包补两集，估算每集 0.6 GB，优于各 0.8 GB 的两个单集包。包内附带已有集的空间也计入成本。它不是每一集的真实大小，也不保证所有资源组合的全局最小容量。

## 报告与颜色

| 状态 | “剧集目录”格 | 应怎么理解 |
| --- | --- | --- |
| 已接受下载且返回任务 ID | 黄底黑字 | 请求已被 MoviePilot 接受，仍需等实际下载并复核。 |
| 本季已有任务 | 黄底黑字 | 本轮没有重复提交，等待现有任务完成。 |
| 只覆盖部分缺集 | 黄底黑字 | 查看“下载未覆盖集号”，剩余集目仍未补上。 |
| 无匹配资源 / 做种不足2 | 浅红底深红字 | 当前可用站点未找到合格资源，不代表互联网都没有。 |
| 网络、登录、身份不明、拒绝提交、结果未知 | 保留原色 | 阅读说明，不能冒充“无资源”或“下载成功”。 |

原表追加：下载处理、下载资源、下载任务ID、下载覆盖集号、下载未覆盖集号、下载时间、下载说明、下载记录及必要续列。人工备注、无关公式、原链接和其他工作表保留。

每轮另加可筛选的 **“下载明细_N”** 工作表：报告位置、剧名、季号、单季整包/单集/零散多集、集号、站点、做种数、资源标题、任务 ID、请求/发现时间、响应时间、说明、资源容量、每个待补集估算容量、中文标记、选择依据、做种数说明。

时间标为 UTC，中国时间需加 8 小时。容量单位为字节，除以 `1024³` 可换算 GiB。整季资源按总容量比较，不填单集估算。做种数是查询时快照，不是当前实时值。

### 为什么做种数为空或“未选定资源”

旧版对“无需下载／待核实”且未选定资源的行留空；v1.2.1 改为“未选定资源”，旁边写明原因。已选定资源的旧记录缺失字段时显示“未记录”，不能当作 0。已有下载任务只有在资源标题和站点唯一匹配时才引用本轮搜索做种数，不将它冒充原任务创建时的数量。旧 Excel 不会自动回填。

明细是本轮快照，重新导入后保留旧页，再增一页；同一页面重复导出不会重复叠加本轮页。跨快照统计时按任务 ID、资源标识和请求时间去重，不要直接把所有页行数相加当作下载次数。机器记录续列必须完整保留，不能截断。

## 防重复与失败恢复

提交前先保存本地记录，随后才发送请求；只有成功响应及任务 ID 才认定接受。开始前也会检查 MoviePilot 已有下载任务。暂停、重新导入旧报告不会跳过这些保护。

超时、刷新发生在提交途中、响应没有任务 ID 等情况，可能已经下载成功；脚本会停止重复提交。先在 MoviePilot/下载器核实，不能靠清空浏览器存储重试。

确认原任务都失败或取消后，使用对应行的“核实任务已取消，解除本季防重复”。该按钮仅解除本地记录，不会取消真实下载；之后需要再手动开始/继续。若旧 Excel 仍包含原下载记录，先按核实结果维护报告，避免又导入旧记录。

第二脚本的整轮 Excel 只在当前页面内存中，刷新前应导出；下载防重复记录跨刷新保留。换浏览器、卸载或清除脚本数据可能失去本地记录，应保留报告并核实下载器现状。

## 常见问题

**找不到 MoviePilotAPI**：当前前端未提供所需页面接口，检查部署兼容性。不要通过写入登录 Cookie/令牌绕过。

**源链接不一致**：核对两脚本 CLOUD_ORIGIN/CLOUD、SOURCE，以及报告是否来自同一云盘；不要随意改动报告路径或季号。

**来源登记集数未确认**：回第一脚本补查并导出新报告；不能按视频文件数猜总集数。

**有资源却未下载**：检查媒体 ID、季号、集号、待播状态、做种数、已有任务及说明。中英文片名相似不能取代身份校验。

**已下载却还是黄色**：黄色表示已提交/已有任务，不负责检查下载完成、云盘整理或版本去重。

## 接口与验证范围

使用 MoviePilot 页面 API；参考 [前端插件接口](https://github.com/jxxghp/MoviePilot-Frontend/blob/v2/src/api/index.ts)、[搜索接口](https://github.com/jxxghp/MoviePilot/blob/v2/app/api/endpoints/search.py)、[下载接口](https://github.com/jxxghp/MoviePilot/blob/v2/app/api/endpoints/download.py)。页面及接口升级可能需要适配。

本地测试使用模拟搜索、下载接口和 XLSX 文件，验证过程中没有向真实下载器提交任务。用户部署环境与默认下载/整理目录需自行确认；脚本不保证下载到的文件质量或字幕实际存在。
