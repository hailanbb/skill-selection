# 剧集整理工作流(后端)

**版本：v1.0.0** · **环境：Windows 11 / Ubuntu 24 + Node.js 22.13+（推荐 Node.js 24）**

一个后端服务，四个阶段：**① 初检 → ② 补缺下载 → ③ 复核清理 → ④ 归档**。

使用 CloudDrive2 gRPC/gRPC-Web、MoviePilot HTTP API 和 TMDB API，替代油猴版的网页操作及浏览器存储。不需要浏览器或盘符挂载；当前没有图形前端，需通过 HTTP API 调用。

[从零安装](INSTALL.md) · [四阶段使用与API](docs/API.md) · [报告与追溯](REPORT.md) · [版本与验证](CHANGELOG.md) · [返回 emby工具](../README.md)

## 选择当前阶段

| 阶段 | 做什么 | 主要入口 |
|---|---|---|
| ① 初检 | 扫描标准季目录，按实际集号与 TMDB 登记核对；明确豆瓣ID可补查 | `/scan`、`/seasons/:id/inspect` |
| ② 补缺下载 | 先检查已有下载，再按整季、中文标记、做种与容量选资源；支持版本补缺及严格历史修复 | `download` / `repair` 计划 |
| ③ 复核清理 | 以明确豆瓣本季信息复核；只保护唯一完整版本，列明多余视频及专属刮削文件 | `cleanup` 计划 |
| ④ 归档 | 核对同剧全部季、源/目标清单；冲突整剧暂缓，验证后清理源目录 | `archive` 计划 |

**启动、导入、生成计划均不自动执行下载、删除或移动。** 默认关闭远程写入；执行需要开启配置，并提交具体计划的确认 hash。网络结果不明时保留记录，不自动重试。

## 第一次使用

1. 按[安装说明](INSTALL.md)安装依赖，复制示例配置并填写自己的接口凭据和源/归档虚拟路径。
2. 启动后查询 `/health`；创建 `/scan` 任务，再从 `/seasons` 取得目标季ID。
3. 逐季执行初检，查看完整性、播期与无法识别文件。来源未知不视为0集。
4. 生成下载计划并审阅后提交；等待 MoviePilot 实际完成下载与整理。
5. 重新检查文件，生成复核清理计划。多个完整版本不自动删除。
6. 对同剧所有绿色季生成归档计划，审阅每个移动和源清理条目后执行；源消失且目标核验通过才标紫。

耗时接口返回 jobId，后续查询任务结果。详细请求体、暂停、核实与报告导入/导出见[操作流程](docs/API.md)。

## 颜色与保护规则

| 状态 | 含义 |
|---|---|
| 绿 | 已确认播完且齐全，无待处理异常 |
| 蓝 | 有明确连载证据，不代表已经齐全 |
| 黄 | 已提交/已有下载或等待复核 |
| 红 | 未找到合格资源或做种不足 |
| 紫 | 归档已实际验证 |

不以视频数量代替集号；不把混版拼齐当成独立完整版本；不按时间淘汰多个完整版本；目标同季冲突整剧暂缓。数据记录在 SQLite，重启不会自动继续外部写入。

## 与油猴版的关系和范围

核心判断模块固定复用[剧集整理工作流(油猴版)](../tv-season-workflow/README.md)的历史版本，网页适配层换成接口，Excel可继续衔接。原豆瓣网页自动候选搜索、访问预算、独立四页复核阶段 XLSX、面板拖动没有搬入后端；豆瓣要求明确ID，复核计划可通过JSON查看。初检按季调用，当前不提供定时无人值守整理或自动回滚。

验证：原业务测试228项、新后端测试12项本地通过；三个服务完成只读接口验证；[Windows/Ubuntu × Node22/24 四组CI](https://github.com/hailanbb/skill-selection/actions/runs/39875452965)全部通过。尚未完成 Ubuntu 24 实机、容器构建及真实云盘写操作验收。请以[验证记录](docs/验证记录.md)为准，不将提交成功视为文件齐全。
