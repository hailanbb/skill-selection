# 原“剧集整理工作流”需求、能力与实现分析

分析日期：2026-10-23。固定源版本：`4dc4ab507bdaae2e7d2412d361a185e9e267e267`。来源为 [GitHub 原项目](https://github.com/hailanbb/skill-selection/tree/4dc4ab507bdaae2e7d2412d361a185e9e267e267/script-tools/tv-season-workflow)，版本证据在 `reference/upstream.json`。本文区分原项目实际能力、后端替换与尚未完成的部署验收，不把原项目文档中的需求自动等同于后端已实现。

## 1. 真实系统边界

这是四阶段有状态工作流，不是四个独立的文件重命名工具。原系统通过 Tampermonkey、CloudDrive2/豆瓣网页 DOM、MoviePilot 页面公开 API、浏览器持久存储和 Excel 联动。没有视频转码、播放质量检测、内容哈希去重或字幕内容识别。

目录契约为 `源根/分类/剧名 (年份) [tmdbid=数字]/Season N/文件`。归档契约为 `目标根/同名分类/完全同名剧集`。特殊篇、未知目录、重复季号和未识别文件不能自动猜测。

输入既包括目录内容，也包括来源登记集数、具体季身份、播出证据、已有下载任务和以前的操作记录。输出既包括颜色和数量，也包括能够解释每一次写操作的逐文件日志。四阶段均不因安装、导入或刷新自动执行。

发布 `.user.js` 是构建产物，内嵌依赖和业务模块，不是另一套独立实现。分析/维护应以 `src` 为准。

### 初检的关键判定

1. 以唯一集号集合核对 `1..N`，文件数等于登记数不能证明齐全。重复、未知、超出范围和季内子目录分别记录；来源未知不是零集。
2. TMDB 先检查剧集 ID、本季号、季摘要数量、逐集编号连续性；集目不完整即拒绝采用。
3. 完结证据要求没有未来/未知播期，并且整剧 Ended 或本季最后一集 finale。其他季续订不否定本季已结束。
4. 原初检按北京时间计算日期，并保守地将核对日当天的集目也视为待播；不是按视频文件出现时间推断。
5. TMDB 不可用、播完证据不足、本地集号超登记范围等会触发豆瓣补查。豆瓣数量本身不能证明播完。
6. 原界面按云盘显示修改时间从旧到新扫描；列表失败不得当空目录，刷新后恢复也不自动运行。

### 补缺下载的关键判定

身份优先级为 TMDB ID、豆瓣 ID，缺少 ID 时只能用完整名称及年份验证。明确冲突的 ID 不能被同名、别名或种子标题覆盖。裸 `S01` 不是全季集号证据；多季资源不能当作单季包。

先排除待播/播期未知的集目。资源最低做种数为 2。同类资源中优先明确中文标记，不因片名是中文而推断有中文字幕。中文条件相同时优先 ≥5 做种组；该组容量全部已知时升序比较容量，否则按做种数降序。没有高做种组时，2–4 做种候选按做种降序。

整季合格包优先；已有覆盖时不重复用整季包。零散多集按 `容量/本次能补上的剩余集数` 估算，逐次重新计算。它是启发式选择，不保证所有资源组合的全局最小容量。

同版本补缺保留发布组、分辨率、来源、编码、音频、HDR 等识别信息，缺少足够证据就不自动换组。混版目录已有下载任务时先等待复核，不能混用不同版本的提交记录抵扣集数。

请求前保存 submitting；只有 success 且存在 download_id 才 accepted。超时、返回格式不明、缺少 ID 进入 uncertain，跨重启仍阻止重复提交。已有任务覆盖范围不明时保守阻止本季新增；现有任务做种低不会绕过排重。

资源最高集号小于登记总数只说明资源站覆盖差异，不构成连载证据；另查具体季播期。已提交/已有任务的黄色优先于连载蓝色。

### 复核清理的关键判定

版本模板只消除集号和明确的“副本/copy”后缀，不合并普通 `(1)`、REPACK 等发布信息。每个版本独立计算完整性：两个不完整版本拼成 1..N 仍不完整。

必须存在唯一可确定的完整版本。多个完整版本或同模板可组成两整套副本时交人工。仅少量同模板重复副本才按云盘文件修改时间保留最新；时间相同/未知则停止。

允许删除多余视频和与该视频唯一对应的 NFO/图片。字幕、公共 poster/tvshow.nfo、未知归属文件和目录保持原样。原版每批最多 50 个，批次前后比较整个快照，部分成功逐文件记账，不重发整批。

绿色同时要求齐全、没有待处理异常和已播完证据。删除成功不等于剧集完结。

### 归档的关键判定

所有实际季必须各自唯一对应绿色行。单季绿色不能代表整剧。播放指针 `.strm`、零字节、大小未知、临时文件、未知子目录、根目录视频、漏季和重复季都阻止归档。

目标分类必须已存在。目标没有同名剧时移动整剧；目标有完全同名剧时逐季及根文件合入。目标有同季，包括 `Season 1`/`Season 01` 等价冲突，或未知根文件同名时，整剧暂缓。

标准根共用图片和 tvshow.nfo 冲突时保留目标版本，源版本列入独立删除清单。这些源文件删除不能记作移动成功。核对目标原内容、移入内容及源剩余内容之后才执行源清理。

“源路径消失 + 目标相对清单一致”是成功条件。目录时间可能变化，文件时间和大小仍需匹配。原项目没有内容哈希验证。

## 4. 构建、测试和依赖脚本

`build.cjs` 读取四个入口，以唯一占位符嵌入 OpenCC、xlsx-js-style 和所需业务模块。它从初检抽取共享纯函数、从清理模块抽取版本函数、从复核适配器抽取只读列目录。边界字符串唯一性断言防止抽取错位。因此不能将 src 文件直接当成 CommonJS require：它们主要是返回工厂的表达式。

新 `app/cores.cjs` 采用同样的明确区段抽取，固定 vendor 快照，执行纯业务工厂；不会执行四个浏览器入口。接口访问由新的 `clients.cjs` 负责。公共第三方依赖 OpenCC 用于简繁统一；xlsx-js-style 处理工作簿和压缩包。原 xlsx 内置 bundle 保持原样，不运行 CDN 代码。

原 21 个测试文件覆盖：archive-empty、archive、batch-cleanup、broadcast-audit、cleanup、cloud-delete、cloud-listing、cloud-move、douban-mixed-alias、douban-policy、douban-titles、download、inspect-navigation、inspect、panel-layout、panel、public-config、review-stage-report、transfer-repair、version-download、workflow-report。它们共 228 项，包含模拟接口/DOM/Excel，不代表真实云盘写入已经验证。

`package.json` 原有 build/test 脚本和 Node≥20 限制；新应用使用 Node≥22.13 的内置 SQLite，推荐 Node24 LTS。原 `snapshot-manifest.json` 是原发布快照说明，不是本后端发布清单。README/INSTALL/REPORT/DEVELOPMENT/CHANGELOG/THIRD_PARTY 及阶段 docs 是使用与维护规范，不是另有可执行任务。

## 5. 状态和数据模型

| 颜色 | 原含义 | 后端值 |
|---|---|---|
| 绿 | 已播完且齐全无异常，或人工确认 | green |
| 蓝 | 有明确连载证据 | blue |
| 黄 | 已提交/已有下载、待复核或清理 | yellow |
| 红 | 没有合格资源或做种不足 | red |
| 紫 | 已验证归档 | archived |
| 无 | 缺集、来源不明、待核实等 | null |

颜色不是唯一真相。原报告人工绿色不能绕过修复未完成、实际漏季或目录冲突检查。后端 plan 保存 row 摘要、操作清单 hash、创建时间；执行必须匹配确认 hash，且计划一小时后过期。SQLite 提交日志早于外部写操作；网络超时保留不确定状态，重启不自动恢复写入。

## 6. 接口替换依据与限制

参考：[MoviePilot OpenAPI](https://api.movie-pilot.org/)、[CloudDrive2 指南](https://www.clouddrive2.com/api/CloudDrive2_gRPC_API_Guide.html)、[官方 proto](https://www.clouddrive2.com/api/clouddrive.proto)、[TMDB TV API](https://developer.themoviedb.org/reference/tv-series-details)。固定接口文件在 reference，服务器实际版本仍需部署现场比对。

CloudDrive 的 API token 放 Authorization Bearer。gRPC-Web 支持 HTTP 反向代理，native gRPC 支持能转发 HTTP/2 的入口。列目录必须读取所有消息并收到成功结束状态，不能将中途失败当空目录。MoveFile 默认冲突枚举为 Overwrite=0；新适配器明确设置 Skip=2，禁用跨云移动和递归冲突处理。

MoviePilot 提供 X-API-KEY、token 查询和 Bearer 等认证方式，用户提供的“token”字段不能仅凭名称确认属于哪一种，运行时用 MP_AUTH_MODE 明确选择。现有资源搜索及下载响应契约沿用原代码；整理修复仍须版本 v2.15.6，不擅自放宽。

豆瓣通过 `/api/v1/douban/{id}` 取得媒体详情后再做标题/年份/本季校验；不会把整剧总集数直接当成本季。缺少季号表达、身份或年度证据就失败关闭。缺少 TMDB ID 的目录不会猜测绑定，需维护正确目录身份或使用已有原报告。

## 7. 后端迁移验收边界

已接通代码路径：目录扫描、逐季初检、资源计划与下载状态机、豆瓣季复核清理、严格历史修复、整剧归档、持久化日志、JSON 报告、初检 XLSX、原 XLSX 导入/分阶段局部导出、请求暂停和只读核实。

尚未等价迁移的原交互：豆瓣网页自动候选搜索/访问预算、独立四页复核阶段 XLSX、原 UI 拖动、按分类/修改时间的交互队列。当前 scan 只登记目录；初检需逐季调用。暂停不取消已经在途的请求；复杂部分成功/不确定结果保留 journal，核实失败时需人工处理，不提供自动回滚或强制解除接口。

Windows 本机已运行后端自动测试及原测试。没有在 Ubuntu24 真机、用户 CloudDrive/MoviePilot 实例上做写入验收，也未验证反向代理的实际 gRPC 能力。提供 Ubuntu systemd/Docker 配置和跨系统 CI，不能将配置文件存在说成部署成功。运行需要实际源/归档根路径及本地环境注入凭据；这些不会从用户示例凭据自动写入配置。
