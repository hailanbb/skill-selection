## 2. 原项目真正解决的问题

原项目是 Chrome / Tampermonkey 上四个独立脚本，用 Excel 交接状态，并非通用文件整理器，也不是 Emby 插件。它没有直接调用 Emby，也不验证视频内容、画质、字幕实际存在或播放可用性。

四阶段：初检 → 补缺下载 → 下载与整理完成后的复核清理 → 整剧归档。下载阶段附带独立的“旧整理历史阻挡修复”分支。

原项目固定目录模型为：源根 / 分类 / 剧名（年份）[tmdbid=ID] / Season N / 文件。Season 0、含糊分季、季内嵌套和未归类根视频不自动猜测。Ubuntu版需支持用户选择更上层的源根目录，不能直接把旧脚本的固定层级套在新根目录上。

| 阶段 | 读取 | 产出 | 外部写入 |
|---|---|---|---|
| 初检 | CloudDrive2 文件列表、TMDB、必要时豆瓣 | 每季数量、缺集、播期、异常、版本清单 | 无 |
| 补缺 | 报告、MoviePilot 下载任务与资源站 | 资源选择、下载记录、未覆盖集号 | 提交下载 |
| 整理修复 | 精确整理历史、下载/整理队列、源目标列表及预览 | 逐集修复清单、结果记录 | 删除指定历史，再单集复制整理 |
| 复核清理 | 黄色项、实际文件、豆瓣本季数据 | 独立版本分组、保留/拟删清单、复核报告 | 确认后普通删除 |
| 归档 | 同剧所有报告行、源目标实际文件 | 整剧移动及源清理计划、验证结果 | 确认后移动与源清理 |

## 3. 初检算法

1. 选择分类或单剧；按目录修改时间从旧到新处理。时间无法解析则提示，不悄悄改成名称顺序。剧内季目录同样按时间处理，同时间再按季号、名称排序。
2. 读取完整稳定列表。原网页实现非空稳定约 1.8 秒，空目录约 0.6 秒，并要求分页为全部；读取失败不能等价于空列表。
3. 从剧目录提取标题、年份和 TMDB ID，从 Season N 提取季号。
4. 从视频文件名提取单个集号，接受 SxxExx、常见 E/EP/Episode、数字“第N集”、纯数字文件名等。明确跨季、多集、冲突编号不猜测。字幕、图片和 NFO 不计视频。
5. 用集号集合计算，视频文件数量与去重集数分开。若登记集合为 R、本地集合为 L、待播为 F、日期未知为 U，则已确认缺集为 `(R − L) − F − U`。出现无法识别的视频时，不能把不完整解析结果当作完整缺集清单。
6. TMDB 必须符合电视剧 ID、季号、连续集目以及登记数量。原初检要求全部集目的日期早于北京时间核对日，并且全剧 Ended 或本季末集有 finale 标记，才确认本季播完。
7. TMDB 不可用、状态未确认、本地超出登记范围时转豆瓣；仅本地缺集、空季或重复文件并不单独触发豆瓣。
8. 豆瓣成功后重新核对集数；失败保留 TMDB 原始数量与诊断；数量与播出状态冲突时不能继承不适用的播完结论。

标题标准化包括 NFKC、简繁转换、不可见字符清理；允许明确别名与完整双语标题，拒绝模糊前缀。第一季最终匹配要求目录年份与标题年或首播年匹配；代码对第二季及以后主要要求具体季号和完整标题，**没有统一强制年份校验**，比文档概括的“核对年份、季号”更宽松。

原初检豆瓣预算：间隔45秒，每20页休息10分钟，滚动40页/小时、200页/天；已播完缓存30天，连载/待播6小时，未知24小时；单项失败24小时退避。登录、验证码和限流需要人工恢复。第三阶段没有共享该预算，实际仅有约3秒等待。这是迁移时应统一的实现差异，不是豆瓣保证的安全额度。

## 4. 补缺下载算法

### 4.1 资格与排序

先验证身份与范围，再排序，不能只拿做种最多或容量最小的结果。

- 身份优先级：TMDB ID → 豆瓣 ID → 完整标题/原名 + 年份。明确冲突 ID 不可用同名覆盖；无 ID 且对应多个媒体 ID 时暂缓。
- 必须是明确的本剧单季，集号覆盖明确，有可用下载入口，做种已知且不少于2。
- S01 字样本身不是整季证据；必须覆盖 1..N，或有与来源数量一致的“全N集”等证据。
- 排除待播/播期未知集、错误季、混季和范围冲突。
- 合格整季包优先，然后才是零散单集、多集资源。普通补缺允许整季包含本地已存在集；已有下载覆盖或混版同版本补齐则有更严格的重叠排除。
- 同类优先明确中文字幕/配音标记；中文片名不算，否定标记不提升优先级。
- 同等中文条件下优先 ≥5 做种组；该组容量全已知时按容量升序，同容量再按做种降序。该组有未知容量，则整组退回做种降序。
- 没有 ≥5 候选时在2—4做种组按做种降序。最终按稳定资源键打破平局。

零散包的单位成本为 `包总字节数 / 本次能补的缺失集数`。每选择一项重算剩余缺集。它是贪心选择，不保证所有组合的全局最小容量；实际提交前会再次查现有任务并重算，排除已覆盖资源。

例如同类同中文：50做种/30GB vs 5做种/10GB，选后者；后者只有4做种则选前者；2做种中文资源可以优先于100做种无中文标记资源。

### 4.2 同版本补缺

按去掉明确集号、保留发布/技术信息和扩展名的文件名模板分组，只去掉明确“副本/copy”后缀，不抹去 REPACK 或普通数字版本。

存在一个完整版本时交清理，不补下载；多个完整版本交人工。均不完整时：能完整补齐的版本优先，然后按该版本最新云盘文件修改时间取较新者；同级时间相同交人工。找资源必须匹配发布组、分辨率、来源、编码、音频、HDR、REPACK/PROPER 等识别签名；缺少唯一标识不换组凑集。

实现主要在识别到多个模板时进入混版选版流程，不能把它概括为“所有单版本目录都已实现严格同组补齐”。旧报告缺版本清单又有混版迹象时要求重检。

### 4.3 防重复

搜索前查现有下载，每次提交前再查；覆盖不明的本季任务阻止追加。提交前持久化 `submitting`，保存失败不发请求；成功且取得任务ID才转 `accepted`；超时或无ID记 `uncertain`，不能自动重发。

MoviePilot 默认下载器与保存目录保持现状，原脚本不创建订阅。下载请求被接受并不等于文件已到 CloudDrive2。

## 5. 整理修复算法

原实现仅适配 MoviePilot v2.15.6、local 存储中的单集普通视频。检查报告必须24小时内，有准确TMDB ID及明确缺集；混版或已有完整版本不走自动修复。

检查严格匹配历史ID、剧、季、集、源存储和源路径，完整读取历史分页；下载或整理仍在进行则暂缓。重新查询源文件属性，调用复制整理预览，要求预览为准确单集、准确目标剧/季，目标没有同名或同集文件。

用户确认下载完成和具体清单后：保存旧历史白名单快照 → 只删除该条历史（deletesrc=false、deletedest=false）→ 再查在途任务、源目标和历史 → 提交单集 copy 整理，scrape=false、reorganize=false。任一步结果不明即停止；只读核实需要新的成功历史和对应目标文件，随后仍由第三阶段核实 CloudDrive2 文件。

Ubuntu 版保留该能力，但根据实际 MoviePilot 版本做兼容性检查。不能因为官方公开文档存在同名接口，就默认用户实例支持所有参数或相同响应。

## 6. 复核与清理算法

默认只处理黄色项。读取文件 → 查豆瓣本季来源 → 再读文件并比较，期间发生变化则不生成可执行计划。

每个文件名模板独立计算 1..N 完整性；多个不完整版本拼起来齐全不能算完整版本。只有一个可确认完整版本才可能自动生成清理计划；多个完整版本、同模板每集都有两份的多套完整副本、版本身份不明均交人工。

同一完整版本的少量重复副本，按修改时间保留最新；最新时间并列停止。保留版本不能缺集，视频大小为零/未知、STRM、未识别视频、临时下载文件、嵌套目录都会阻止自动清理。

删除范围仅限明确多余视频及唯一对应的 NFO/图片；字幕、共用资料、归属不明内容保留。默认每季最多50文件一批，逐批写日志、刷新、确认删除项消失且保留项未变。部分成功分开记录，不重发整批。暂停先处理当前已发请求的结果，再停止新批次。

清理后需重新扫描，且本季播完、齐全、无未闭环修复/删除状态才标绿。另有“复核阶段报告”四页：概况、逐项复核、版本分析、文件计划；其拟删除记录不会被后续执行改成已删除，它不替代跨阶段报告。

## 7. 归档算法

候选是含绿色行的整部剧，检查时读取同剧所有颜色。所有实际季必须唯一对应绿色行；漏季、混色、重复行、目录级未知、未闭环修复均阻挡整剧。

实时检查集号连续、数量、非零视频大小、重复视频、临时文件、嵌套结构。原实现允许人工绿色且来源数量空白的连续非空季进入归档预检；Ubuntu 版应保留为显式“人工确认”而非伪装成自动来源验证。

- 目标无同名剧：整剧移动。
- 目标有完全同名剧：合入全部无冲突季及根文件。
- Season 1 与 Season 01 是同季冲突，整剧暂缓，不先搬其他季。
- 未知同名根文件冲突也整剧暂缓。
- 标准共用根资料如 tvshow.nfo、poster.jpg 等，目标是非零普通文件时保留目标，源副本明确列入删除计划；不是内容去重，也没有比对图片是否相同。
- 迁移后验证目标原内容及新移入内容，源只剩清单内重复共用资料或为空时才能清理；源路径消失后才标紫。

验证依据路径、类型、大小和文件修改时间，不是媒体内容哈希。目录修改时间可因移动改变，不能直接作为移动失败依据。原预览仅缓存目标根及分类列表60秒，执行和验证用实时列表。

## 8. 报告、构建与迁移注意

Excel 是原项目的流程协议：只给“剧集目录”格上色，一季一行。绿=可归档候选，蓝=有连载证据，黄=已提交/已有任务/待复核，红=当前无合格资源，紫=归档已验证；颜色不是完整业务状态。

原报告模块保留原 XLSX 压缩包，局部修改必要 XML 单元格，保留其他备注、公式、链接和工作表；拒绝身份公式、条件格式等不能可靠解释的输入。限制30MB压缩文件、150MB解压大小、表格50000行和301列扫描边界；操作明细最多50000行。机器记录按约30000字符分列。

Ubuntu 版用数据库保存事实、状态、计划和操作日志，Excel 是兼容输入/导出，不要求阶段间反复上传下载。旧颜色导入为带来源的人工工作流标记，不得覆盖更新的待核实写操作记录。保留原报告字节与备注，导出新文件。

`build.cjs` 从源码用字符串边界抽取共用函数，再嵌入 OpenCC、XLSX 库形成四个安装文件。运行环境依赖 DOM、GM存储、GM开页、MoviePilotAPI和浏览器互斥锁。Ubuntu 移植应拆出显式模块及依赖接口，替换这些平台适配；不要将整份油猴脚本放进虚拟浏览器长期运行。

建议保留 JS 算法并整理为 TypeScript/Node 模块，降低重写排序及边界规则的风险；SQLite 保存任务，systemd 管理进程。语言是实现建议，不影响用户命令；无需额外引入 Redis、数据库服务器或Web管理站。

## 9. 已发现的差异与需修正项

| 问题 | 证据与影响 | 迁移处理 |
|---|---|---|
| 初检版本清单漏大小 | season-inspect.readRows 没读取 size，scanShow 却写 f.size；version-download 会拒绝大小未知，额外模拟已复现 | API统一采集原始字节大小，加入初检到下载的贯通验证 |
| 当日播期规则不一致 | 初检 air_date<today；broadcast-audit 使用<=today；同一两集案例分别得到连载中和已播完，已模拟复现 | 统一时区及“仅日期”规则；建议延用原初检保守语义，当天不直接算已播完 |
| 豆瓣年份检查并非所有季一致 | candidateMatches 最终仅第一季强制年份匹配 | 区分全剧首年和该季首年，缺证据时提示；规则变更需明确记录 |
| 豆瓣预算分裂 | 初检独立预算/缓存，复核没有共享 | 统一数据提供器、缓存、限速和暂停状态 |
| STRM阶段语义不同 | 初检视为媒体，清理/归档明确阻止 | 显示为播放指针类型，提前说明不可自动清理/归档 |
| 日志防重不等于后台恢复 | 多个阶段会话、计划或阶段报告在页面内存 | 数据库持久化任务、计划、批准范围、每次尝试和结果 |
| 文档和版本信息有漂移 | package版本、分阶段版本不同；DEVELOPMENT提到不存在的inspect-navigation.js | 单独列组件版本，源码和测试为判定依据 |

此外，初检版本清单的分片会避开 UTF-16 代理对边界，而后续报告分片直接 slice；迁移时应统一 Unicode 安全分片，避免包含扩展字符的长记录在 XML 往返中损坏。这是静态风险，未在本次额外模拟中复现。

## 10. API 设计与已核对能力

### CloudDrive2

官方文档和 proto 提供 GetSubFiles、FindFileByPath、MoveFile、DeleteFile、DeleteFiles。推荐通过 gRPC；反向代理只有 gRPC-Web 时再配置兼容传输，不能把“网页地址可访问”视为原生 gRPC 已通。

- GetSubFiles 为服务器流，需完整收集并确认正常结束；流中断所得部分目录不能用于缺集、删除或归档。
- forceRefresh 用于写前、写后核实；保留原始 size、writeTime、id、fullPathName。int64大小和时间精度不能被显示格式舍入。
- MoveFile 显式设置 Skip 冲突策略，不使用 Overwrite；禁用递归冲突合并和跨云移动。Skip可能导致未移动，所以仍须逐项核实，不能拿 success=true 直接标紫。
- 只调用普通 DeleteFile/DeleteFiles，不调用 Permanently；普通删除能否恢复取决于远端存储，不承诺全部都有回收站。
- 原生接口未提供整个整剧流程的事务锁。程序自己的锁不能阻止 MoviePilot 或别人同时改文件；每步核对可降低风险，但无法消除核对与操作之间的竞态。源目录删除尤其要在无并行写入的操作窗口进行，出现变动即停。

### MoviePilot

已读取用户提供的 Swagger 页面实际加载的 openapi.json。公开文档 info.version 为0.1.0，不能当成用户服务版本。下列接口须由安装自检确认用户实例兼容。

| 用途 | 官方文档中的接口 |
|---|---|
| 媒体候选搜索 | GET /api/v1/media/search，title/type/page/count/source |
| 豆瓣指定条目详情 | GET /api/v1/douban/{doubanid} |
| TMDB媒体详情 | GET /api/v1/media/{mediaid}，type_name等 |
| TMDB指定季集目 | GET /api/v1/tmdb/{tmdbid}/{season} |
| 查正在下载 | GET /api/v1/download/ |
| 搜资源站资源 | GET /api/v1/search/media/{mediaid} |
| 提交下载 | POST /api/v1/download/ |
| 整理历史 | GET / DELETE /api/v1/history/transfer |
| 单集整理预览与执行 | POST /api/v1/transfer/manual |

当前公开规范列出 X-API-KEY 等认证方法；优先使用实际实例支持的请求头认证，避免把秘密拼入命令行或URL。设计阶段不读取用户凭据、不创建或修改令牌。

### 豆瓣经 MoviePilot API：首选方案

1. 已绑定豆瓣ID的季直接取详情；未绑定时通过 MoviePilot 媒体搜索按豆瓣来源检索，读取完整候选页。
2. 以 douban_id、title、original_title、names、year、season/seasons/season_info 等实际返回证据验证本剧本季，不只凭搜索排名。
3. MediaInfo 中存在 number_of_episodes、seasons、status 等字段，但字段可空或默认0；数量0不能直接解释为零集，不能默认总集数等于当前季集数。
4. MoviePilot 的季字段可能由标题推导，没有明示季号可能被整理成第一季，不能把这种默认值当作独立证据。原网页读取的首播年列表、原始别名和明确完结文字不保证全部透传。
5. TMDB集目和结束/季终证据仍通过 MoviePilot核对；只有豆瓣数量时保持播完未知。数量冲突保留两套证据，不用一方静默覆盖另一方。
6. 找不到唯一候选或无法确定季号、数量或播期时，在结果和报告中列明原因，暂缓该项；不增加作品身份/来源绑定菜单，不自动改用网页或虚构判断。
7. 统一缓存及请求退避。原脚本“网页页数”无法等价为 MoviePilot 请求数或上游实际访问数，因此不能照抄网页预算并声称已控制豆瓣全部请求。
8. 保存“数据来源=豆瓣、获取通道=MoviePilot、查询时间、条目ID、匹配依据”。API请求时间不一定是上游抓取时间，不能伪称实时豆瓣数据。

因此纯API架构可行，豆瓣也优先走API；但“所有复杂别名/分季案例与原网页逻辑等价”必须用用户实例响应验证。API缺证据时仅阻挡相应季，不堵住其他独立剧集。

## 11. 推荐的 SSH 操控方式

### 主入口：数字菜单 + 任务优先

输入 `tvflow` 进入中文菜单。采用普通终端文本，默认不强制全屏、不依赖鼠标或特殊字体；全屏方向键界面可后续作为可选增强。

```text
剧集整理工作流                         远端服务：CD2 正常 / MP 正常

当前任务：J024 初检 · 韩国剧集 · 23/86 部
需要处理：3 个来源待确认 / 2 份清理计划 / 1 个操作结果待核实

1  开始新的检查              2  补缺下载
3  复核与版本清理            4  归档
5  查看任务与进度            6  处理待确认项目
7  导入 / 导出报告           8  连接设置与诊断

r 刷新   / 搜索剧名   b 返回   q 退出菜单（后台任务继续）
请选择：
```

菜单内容均为设计示例，不是已运行的界面。数字编号在当前视图稳定；刷新会明确提示列表变化，选中对象以固定ID校验，不能因刷新让数字对应另一部剧。

选择范围不要求输入长中文路径：连接→分类→剧集/季列表。搜索可输入部分剧名、TMDB ID或任务ID。列表编号批量选择支持 `1,3,5-8`；`a` 选择当前明确筛选结果，并显示数量；不把后台新出现项目偷偷加入已选择范围。

大列表提供状态筛选与分页，详情显示完整路径。短列表按列显示；窄终端改成逐项卡片，长路径可复制且不以截断路径执行。`NO_COLOR`/非TTY输出使用纯文本，脚本调用另有JSON格式。

### 新建任务向导

选检查 → 显示当前源根并读取实际目录 → 选择电视剧/动漫等目录及子分类 → 选择全部或指定作品/季 → 显示范围和只读性质 → 开始 → 立即返回任务ID。分类扫描默认保持原来的旧到新顺序。范围、连接和路径显示在启动摘要中，防止操作错服务。

### 当前源根目录与分类浏览

首次使用默认 `/115/Library_incs/nas/`。该值是CloudDrive2虚拟路径，不是Ubuntu本地目录；不自动追加“电视剧”。内部可统一末尾斜杠，但必须保持真实目录身份。

初检选择页始终显示当前源根，提供 `s 设置根目录`、`r 刷新`、`b 返回`。设置支持直接粘贴绝对路径或通过API逐层浏览，列出实际子目录；选定后只读验证目录存在、可读取，才保存。网络、权限或流读取失败不能显示为“目录为空”。

用户可以选择“仅本次使用”或“保存为默认”，以后启动读取保存值；“恢复默认”恢复到上述初始路径。已开始任务和已确认计划固定绑定原连接、源根、具体对象及目标，不因修改当前根目录而转向新位置。

示意菜单如下，目录名称、编号与数量以实际API返回为准，不预设用户真实目录结构：

```text
当前源根：/115/Library_incs/nas/

1  电视剧/
2  动漫/
…  其他实际子目录

输入编号进入目录；选择处理范围时可批量勾选
s 设置根目录    r 刷新    b 返回
```

源根提升一层后，“电视剧”“动漫”可能是媒体集合，其下可能还有地区分类，也可能直接放作品。因此浏览与识别分开：通过目录内容识别“集合/分类/作品/季”，展示候选层级；无法确定时在结果中列为结构待核实，不提供目录用途配置菜单，不把第一层文件夹一律当作品或分类。可在一次任务中选择多个范围，嵌套或重叠选择去重，避免同一季扫描两次。电影、杂项及未知结构不能仅因位于源根下就套用剧集规则。

作品记录保留源根下完整相对路径及各层目录，不再依赖旧脚本固定的“分类/剧名”拼接。归档预览沿用确认的相对层级，例如 `电视剧/韩国剧集/作品` 与 `动漫/日本动漫/作品`，保持两类内容分离；目标根由用户另行设置，不从新源根猜测。若用户将更深目录设为源根，须重新展示并确认归档映射，不能静默改变目标层级。源根与归档目标仍须独立、不相互包含。

### 动漫与剧集共用四阶段

“动漫”作为可选择的媒体集合，不另做一套操作方式。季集身份明确的动漫采用相同的来源核对、缺集集合、同版本补齐、完整版本保护、逐文件清理计划和整部作品归档规则；排序仍遵守整季、中文标记、做种及容量优先级。不会仅因为动漫分类而新增画质、字幕组排名或强制换版本规则。

元数据仍优先通过MoviePilot获取TMDB与豆瓣数据。动漫目录分类不等于媒体身份，自动下载仍需确认电视剧类型、具体作品、季与集；动漫电影/剧场版不能当成某一季自动处理。

| 动漫目录/命名情况 | 设计处理 |
|---|---|
| 已有Season N及明确SxxExx文件名 | 直接采用现有四阶段规则 |
| 季目录内纯数字、明确E/EP编号 | 使用已有解析能力，仍检查来源季与编号范围 |
| 作品直接放视频，未分季 | 缺乏明确季号时列为结构待核实，保留文件并输出原因；不提供目录结构或季集映射配置菜单 |
| 长篇绝对集号与来源分季编号不同 | 无法用现有明确季集规则确认时暂缓；不猜减去偏移量，不增加手工集号映射模块 |
| 上下半部、分割季度、不同来源分季不一致 | 来源不足或冲突时列为待核实；不得把全作品集数当作一季集数 |
| Season 0、SP、OVA、OAD、NCOP/NCED、特典 | 单独列出、保留；不算正片缺集，不作为多余正片删除；未确认内容阻挡整部归档 |
| 合并集、字幕组命名导致版本无法确认 | 列出具体文件和原因；不猜测版本，不因多个组拼齐就自动清理 |

根据用户简化操作的要求，取消目录结构/季集映射模块，以及作品身份/来源绑定的用户菜单。程序内部继续自动核对身份、季号和来源；无法确认的项目记录具体原因、暂缓自动写操作，用户处理源数据后可重新检查。不因取消菜单而取消业务校验。

无法确认季结构的作品不自动归档，不自动改造目录结构。全部改名、建季目录或文件重排均不属于当前默认整理行为。

导入旧Excel保留原根目录与旧路径规则；新根目录和可变层级使用版本化的新报告字段。不能把这类新报告伪装成旧 `tv-workflow/1` 并承诺油猴脚本可直接执行；导入/导出页需明确标注兼容范围。

不做“一个按钮从初检自动删到归档”的默认动作。检查结束后显示下一步建议，用户可将选中的季交到下一阶段，不需要重新导入Excel。

### 计划预览与执行

补缺直接根据当前初检任务结果自动确定对象，不要求用户再次逐剧或逐季选择；默认显示关联任务编号、范围与结果时间，必要时可切换其他初检任务。点击“开始补缺”前展示范围及沿用的选择规则，确认本轮后自动搜索、选资源并提交，沿用原工作流的批次启动授权。不设独立“查看已有下载计划”模块，不要求逐资源批准。来源不明、已有任务或结果不明仍按业务规则暂缓或跳过；本轮对象固定，新出现的对象不自动加入。

清理、修复、归档仍在本阶段内展示具体保留/删除/移动清单，确认后执行；无需跳到单独的计划管理模块。下载候选和选择原因作为运行详情与报告记录，不作为必经菜单。

```text
计划 P031 · 清理 · 2季
保留视频 24个    拟删视频 5个    拟删专属图片/NFO 7个
字幕和共用文件保留    预计处理12个文件

1 查看保留版本和原因
2 查看逐文件删除清单
3 查看全部保留文件
4 导出计划
e 确认执行此计划     b 返回
```

输入 e 后显示计划ID、范围、数量及动作；删除/移动确认要求输入 `执行 P031`，默认回车为取消。该确认只绑定当前计划的内容摘要，不授权今后新计划。相同计划暂停后继续不重复确认，计划、来源、目标或规则变化则旧批准失效。

下载执行页实时显示资源名称、集号、站点、做种、容量、中文证据和选择原因；每次提交前仍检查最新下载列表，按本轮已确认规则重新计算。出现身份、覆盖或操作结果不明时暂缓，不使用猜测结果继续下载。

人工选保留版本是新增交互能力：只允许在已有完整版本中明确选择，先生成全新清理计划；选择本身不删除，不允许绕过不完整版本或未知归属的保护。

### 所有阶段统一的实时进度与结束输出

初检、补缺、整理修复、复核、清理和归档在启动后默认进入彩色实时进度页，无需再次选择“持续观看”。页面显示任务ID、阶段、当前范围、已处理/总量、当前作品/季/文件、当前步骤、耗时、最近进展时间以及滚动事件。终端渲染可每秒刷新，远端API按合理频率查询，不把刷新屏幕等同于每秒请求服务。

扫描目录尚未完成、总量未知时显示“正在发现目录，已发现N部”，不用虚构百分比；总量确定后显示进度条。初检按作品并补充季数，补缺按季及资源提交数，清理按已核实文件/批次，归档按作品及移动单元展示。没有远端字节进度时不显示虚假的传输百分比或精确剩余时间。后台写操作已发出但尚待核实，不能计入已验证成功数。

实际SSH使用ANSI颜色：绿色=本步骤已验证成功，蓝色=运行/连载等需结合文字理解的状态，黄色=等待/待核实/有提醒，红色=失败或无合格资源并明确区分原因，紫色=归档已验证，灰色=跳过。始终同时输出文字标签；支持无色终端与NO_COLOR，保存日志不携带控制码。阶段报告既有颜色语义保持不变，例如下载已接受仍为黄色，不标成文件齐全。

每阶段完成、用户暂停、停止后续处理或可处理的异常退出时，自动保存当前结果并生成XLSX报告、CSV报告、完整JSON记录及日志，输出任务状态、起止时间/耗时、阶段统计，以及每个已生成文件的名称和完整绝对路径，不再要求用户手动点导出。异常掉电时以持久数据库为恢复依据，重启后补生成中断报告，不能承诺进程被强杀时仍即时写完报表。

报告、完整记录和运行日志的保存目录可分别自定义。默认建议分别为运行用户的 `~/.local/share/tvflow/reports/`、`~/.local/share/tvflow/records/` 和 `~/.local/share/tvflow/logs/`，均按任务分子目录；显示时展开为真实绝对路径。XLSX与CSV保存在同一报告目录，JSON保存在完整记录目录，日志保存在运行日志目录。文件名包含阶段、范围、时间和任务ID，重复导出另存，不覆盖唯一旧报告。各文件独立写入并校验成功后才显示“已保存”；部分导出失败逐项说明并保留数据库结果，不能打印虚假可用路径。

CSV采用面向Windows Excel/WPS的UTF-8 BOM、逗号分隔、CRLF换行及规范引号转义，中文内容须往返验证。CSV不能保存颜色、超链接样式或多工作表，因此显式提供状态与原因文本、链接文字；XLSX中的主表和各操作明细表分别输出为有清楚名称的CSV文件，不能只导出主表而遗漏明细。未知值保留为空或明确的“未确认”，机器ID和前导零字段不得静默转成数字；对可能被表格软件执行的外部文本采用防公式注入处理，不把CSV作为无损机器记录，完整数据仍以JSON及数据库保存。CSV用于查看和分析，不作为旧油猴流程的颜色交接输入。

### 输出保存路径设置入口

统一入口：“主菜单 → 8 设置与连接诊断 → 7 报告与保存路径”。其中子菜单为：

```text
报告与保存路径

1  设置报告目录（Excel / CSV）
2  设置完整记录目录（JSON）
3  设置运行日志目录
4  查看当前全部保存路径
5  检查目录可写性
6  恢复默认保存路径

b  返回
```

这里填写Ubuntu控制端的本机目录，不是CloudDrive2虚拟目录或MoviePilot路径。支持输入绝对路径或浏览本机可访问目录；设置流程在目录不存在时提示创建，并以实际后台服务运行账户检查可写性，通过后持久保存。设置不移动或删除旧文件，不自动调整目录权限；已有任务固定使用启动时的保存路径，修改仅影响新任务。恢复默认需显示将变更的三条目录并确认，只更改设置，不清理旧产物。

任务结束页分别输出Excel、各CSV、JSON及日志的实际名称和完整路径，即使三类文件位于不同目录也能直接定位；不只显示共同父目录。菜单“报告与保存路径”负责上述输出位置，终端配色和分页设置保持独立，不与路径设置混淆。

统计至少包含：初检的作品/季总量、齐全、连载、缺集、待核实和读取失败；补缺的自动纳入/跳过季数、新提交资源/覆盖集数、已有任务、无资源、部分覆盖和结果不明；复核清理的复核季数、完整版本、待人工项、计划/已验证删除/剩余文件；归档的候选、已验证归档、冲突跳过、待核实、源目录清理结果；整理修复的检查、可修复、已提交、待文件复核和结果不明。互斥主结果与可交叉的明细计数分别标注，避免重复相加误解。

初检完成页提供“1 按本次结果开始补缺、2 查看异常详情、3 重新检查、b 返回主菜单”。补缺自动使用本次结果，不再次勾选补缺对象；报告生成失败时仍明确展示持久结果状态。

### 归档根目录设置入口

主入口为“主菜单 → 8 设置与连接诊断 → 2 归档根目录”。支持CloudDrive2目录浏览或直接输入路径，验证目标存在、可读且与源根独立后保存。归档页面顶部始终显示当前目标，提供 `s 设置归档根目录` 捷径；首次未配置时先完成设置，再检查候选。初始归档根不猜测，等待用户设置。

修改目标后旧计划不会自动改指新目标；尚未执行的归档需重新预览确认，已运行任务继续绑定原目标。设置本身不创建、移动或删除云端目录。

### 任务页与断线

```text
J024  初检  运行中  23/86部  最近进展 8秒前
当前：示例剧 / Season 2 / 等待 MoviePilot 元数据

w 持续查看   l 最近日志   p 请求暂停   b 返回
```

- SSH断线、菜单退出、Ctrl+C退出观看：后台任务继续；CLI明确提示这一语义。
- 暂停是显式操作：停止新请求，已发送写请求先核实；超时则进入待核实，不无限卡在“暂停中”。
- 重新登录输入 tvflow 就能看到正在运行、暂停、待确认和失败任务。
- 服务器重启/服务崩溃：恢复数据库，但未完成写操作先标待核实，不自动重发；未开始部分停在暂停状态等待用户继续。
- 停止本程序任务不等于取消 MoviePilot 已提交下载，界面明确区分。首版不提供隐含取消下载器任务的“停止全部”。
- 任务完成不是归档完成。等待下载的状态有上次查询时间和下一次检查时间；只读轮询可在用户启动的跟踪任务内持续，超时不会偷偷发新下载。

### 短命令作为捷径

以下为拟议命令，不是当前已安装能力：

```bash
tvflow                         # 中文菜单
tvflow status                  # 全局任务摘要
tvflow inspect --category "韩国剧集"
tvflow watch J024               # 观看任务；退出不停止
tvflow pause J024
tvflow resume J024
tvflow needs                   # 需要人工处理的事项
tvflow plan show P031
tvflow plan execute P031        # 展示计划并交互确认
tvflow reconcile J024           # 只读核实，不重发写操作
tvflow export J024 --format xlsx
tvflow doctor                  # 只读连接/能力诊断
```

无需记忆命令：菜单可显示“等价短命令”，逐渐熟悉即可。支持Tab补全短ID。非交互模式没有TTY时不弹问题、不自动接受确认；写操作若将来允许自动化，必须绑定预先批准的具体计划摘要，不使用全局永久 yes。

## 12. 后台与数据设计

Ubuntu运行一个systemd管理的工作进程；菜单/CLI通过本机Unix socket通信，无需对外开放一个新的管理端口。后端负责持久队列，CLI只是控制器。默认首版单外部写队列，同剧各阶段互斥；并行只读也不得与该剧清理/归档冲突。

数据分开存：连接配置、剧/季身份、实际文件快照、来源证据、版本组、任务、不可变计划、确认记录、逐次操作日志、人工备注。内部事实至少分为：来源是否确认、播出状态、完整性、版本状态、下载状态、写操作状态；颜色由这些事实派生。

每次外部写操作遵循：计划审阅 → 记录批准 → 刷新并比对 → 先记准备状态 → 发一次请求 → 查询验证 → 记录结果。数据库不能与远端API组成一个事务，因此不承诺网络异常下“严格恰好一次”；用未知状态和只读核实阻止盲目重复。

本地锁仅约束本程序；多Ubuntu控制端同时操作同一目录不在首版支持范围。即使采用单实例，也须应对 MoviePilot 和人工操作导致的远端变化。

配置把三类路径明确分开：CloudDrive2虚拟源/归档路径；MoviePilot看到的下载源/整理目标路径（可能是容器内路径）；Ubuntu本机数据/报告路径。不因为字符串相似就推断它们是同一实际目录。

内部保存UTC和原始时间，终端默认显示Asia/Shanghai并注明时区，播期判定采用同一时区策略。文件名不做简繁或大小写改写，名称匹配与真实路径寻址分开。

数据库定期备份，升级前备份状态并完成必要迁移校验；它只能恢复程序记录，不能恢复已删除媒体。首版不承诺自动回滚远端删除/跨目录移动。

## 13. 开发前后的验收安排

先定操作方案，再开发。实际接入时先用用户实例进行只读能力探测：Ubuntu版本与架构、CD2版本及gRPC传输、MP版本与OpenAPI、认证方式、目录和路径映射、元数据字段完整性。此处尚无用户实例地址和版本，因此兼容性仍未验证。

开发验收按行为推进：

1. 原业务判定测试迁入，补初检→版本补缺贯通和日期规则测试。
2. 只读真实分类/单剧扫描，对照原报告核实来源、缺集、顺序及中文。
3. 菜单在普通SSH、窄终端、无颜色、无TTY、重复登录中可用；SSH断线后任务继续，进程重启后写任务不会重发。
4. 对API流中断、分页重复、认证失效、请求超时、成功响应丢失、大小/时间变化、部分删除、移动冲突进行故障验证。
5. 用户明确授权的测试目录和下载对象中验证真实写操作；先小范围验证，再允许批量。模拟测试通过不替代这一项。
6. Excel保留人工备注/公式/链接/历史工作表，导入旧报告不能覆盖更新防重日志。
7. 默认根为 `/115/Library_incs/nas/`；通过API读取电视剧、动漫及多层子分类；支持临时切换和保存默认，旧任务范围不随设置改变。根不可读、目录层级不明、重叠选择均有明确处理。
8. 同一标准季结构动漫样例贯通初检、版本补缺、清理和归档；另外验证无季目录、绝对集号、分割季度、特别篇、混字幕组及动漫电影不会被误当普通缺集或多余文件；不增加手工映射和身份绑定菜单。
9. 所有阶段启动默认彩色实时展示；总量未知不伪造百分比；结束/暂停自动输出统计及已成功保存的报告名称和绝对路径。补缺从当前初检结果自动确定对象，不要求二次逐项选择；归档目标设置入口和当前目标始终清楚可见。

首版完成标准是四阶段与整理修复均有明确入口和状态、需要用户判断的情况可在SSH处理、所有计划及结果持久可追溯。定时自动处理、网页面板、消息推送和多节点协作不属于本次已确认范围。
