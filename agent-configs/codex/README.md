这是供 **OpenAI Codex** 使用的个人全局行为规范，版本 **1.2**，更新于 **2026-09-08**。适合中文沟通、Windows/中文路径与编码环境，以及需要明确自主执行和批准边界的工作流。

[查看 AGENTS.md](AGENTS.md) · [返回仓库首页](../../README.md)

## 分类与适用范围

本文件属于「Agent 配置与行为规范」，独立存放在 `agent-configs/codex/`。它是持续适用的协作规则，不是按场景调用的 Skill，也不是 MCP 服务，不放入 `skills/` 或「精选技能索引」。

这是为 Codex 整理的个人模板，不是 OpenAI 官方预设。文件名 `AGENTS.md` 本身并不专属于 Codex，但本版本的加载说明、平台边界和工具约定面向 Codex。Claude Code、Gemini、Antigravity 及其他 Agent 使用前，需要按各自的规则加载机制和权限重新适配；本仓库未验证它们直接使用本版本的效果。

## 规则覆盖什么

- **自主执行**：已授权的常规工作直接推进，必要信息才澄清；多文件修改先通知再继续。
- **批准边界**：发送、发布、购买、凭据、安全和破坏性操作保留明确批准要求；同一具体授权在范围不变时避免重复询问。
- **完成与验证**：按影响选择检查，保留项目必需验证，不重复运行无关测试，也不把工具成功等同于交付完成。
- **中文与 Windows**：明确编码、BOM、换行、中文路径、结构化数据及 Excel/WPS 消费者验证。
- **沟通与维护**：中文默认、结论先行、减少模板化回复；区分全局偏好、项目规则和 Skill 适用范围。

该文件不能提升工具权限或绕过沙箱，也不会安装工具、启用实验功能、切换模型或自动开放子 Agent。实际能力及权限取决于当前 Codex 环境。

## 安装与启用

1. 下载本目录的 `AGENTS.md` 原始文件，或从仓库副本取得该文件。不要将 GitHub 网页另存为 Markdown。
2. 确认你的 Codex 配置目录。默认路径如下；设置了 `CODEX_HOME` 时使用其指向的目录。

   | 环境 | 默认全局文件位置 |
   | --- | --- |
   | Windows | `%USERPROFILE%\.codex\AGENTS.md` |
   | macOS / Linux | `~/.codex/AGENTS.md` |

3. 已有同名文件时，先备份并比较规则，保留自己的项目约束、偏好及批准要求，再合并或替换。尤其审阅凭据操作、一次批准的范围和本次临时产物清理条款。
4. 将文件放到上述位置，保持文件名为 `AGENTS.md`。不要放进 `.agents/skills/`、Gemini 的技能目录，或重命名成 `SKILL.md`。
5. 新开 Codex 会话，要求它列出实际加载的规则来源，并概括批准边界与中文偏好。不要把当前旧会话视为已经自动重载。

Codex 在全局目录优先读取非空的 `AGENTS.override.md`，否则读取 `AGENTS.md`；如果新规则没有生效，先检查覆盖文件及 `CODEX_HOME`。项目目录内的规则也可能覆盖全局的相关偏好。具体加载方式以 [OpenAI 官方 AGENTS.md 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)为准。

只想在一个项目试用时，先合并到该项目现有的 `AGENTS.md`，不要直接覆盖项目事实、构建命令和验收要求。本仓库目录是模板存放位置，仅下载仓库不等于安装为全局规则。

## 首次使用检查

在新会话中用说明性问题核对即可，无需真的发送、购买或删除文件：

- 请列出当前实际加载的规则文件，并说明这份 Codex 规则是否适用。
- 如果只要求“准备邮件”，是否会直接发送？预期：准备草稿，发送需要明确授权。
- 修改一句中文说明时会做哪些验证？预期：相关内容、编码和差异检查；不自动扩大到无关测试。
- 如果已经批准某个具体动作，后来对象或影响范围变化，会如何处理？预期：确认变化部分。

Windows/中文环境是本版本重点；macOS/Linux 上的通用协作规则可参考使用，但未提供所有客户端与环境的行为测试保证。此版已核对源文件一致性与中文编码；新会话表现仍需按上述方式检查。

## 编码、更新与回滚

发布的 `AGENTS.md` 保留本地正式版的 **UTF-8 BOM + LF**，正文与已批准的 1.2 版一致。说明文档使用 UTF-8。不要因编辑器默认行为意外改变中文、BOM 或换行。

更新前备份当前全局文件，比较差异后再合并；恢复时使用自己的安装前备份，并新开会话核对。仓库 Git 历史用于追踪模板变化，不能替代你个人原有配置的备份。
