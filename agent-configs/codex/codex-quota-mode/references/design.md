# 全局省额度模式：分析、设计与验证

版本 1.0 · 2026-09-08 · Codex 专用

## 最终选择

用户明确选择按文章截图保留 **GPT-6 Astra / high** 主线程，用 **GPT-5.6 Luna / medium** 执行适合委派的工作。因此本版不采用上游当前的 low 主线程，也不偷偷改成 Luna 主线程。

开关是全局默认配置 + 全局规则的可回滚切换。开启不要求每个任务都派子 Agent，也不承诺一定节省配额。创建并安装 Skill 后默认不启用；用户明确说“开启省额度模式”才生效。

## 文章的价值与问题

依据本地文章《目前最聪明的_Codex_省额度方案_Astra_当总指挥_Luna_批量干活_附全套配置.md》，并于 2026-09-08 核对上游项目 `f1de1b8729c8ccfb7978321b4764c58bd34c8493` 和官方文档。

| 文章观点或做法 | 核查与设计决定 |
| --- | --- |
| Astra 管决策、Luna 做执行 | 保留，但按任务收益委派。架构、接口/数据与鉴权决定由主 Agent 负责；委派不等于放弃验收。 |
| 两分多钟耗尽 Plus 配额 | 单人经历缺少任务规模、其他会话、缓存与重试数据；不能推导每个人的额度速度。 |
| 用低价 Luna 就能保护绝大多数额度 | API 计价与订阅额度不是同一个口径；主线程协调、上下文复制和返工也有成本。本版不提供虚构节省比例。 |
| 五个角色全部锁定 Luna | 上游当前版本的 reviewer 已设为 Astra，文章不是其当前代码的完整描述。本版不创建角色文件，按任务直接指定 Luna，主线程验收，避免额外 Astra reviewer 常驻。 |
| Astra 固定 high | 当前上游示例已是 low，另提供 Plus 的 Luna/max 主线程版本。用户选择仍用 Astra/high，本版明确尊重这一取舍。 |
| 无论默认如何改，子 Agent 永远是 Luna | 官方说明显式 spawn 参数可覆盖默认；full-history fork 还可能继承主模型。本版每次明确 Luna/medium 并使用最小上下文，不把配置当成运行证据。 |
| 五角色流水线和 6～8 路并发 | 容易重复读取、拆得过细并增加文件冲突。默认最多 2 路、禁止递归委派；简单任务直接做，依赖步骤串行。这个上限是本设计的保守选择，不是平台能力上限。 |
| 复制整个 .codex、.agents、AGENTS.md | 会覆盖用户现有设置与行为约定。只修改六个配置键，AGENTS.md 追加受管块，不触碰 MCP、沙箱、审批、服务档位、角色文件或项目文件。 |
| 放进项目就自动有效 | 项目可信度、加载时机及其他配置层影响实际结果。用户需要全局模式，因此写 Codex home；新会话加载，旧会话不假称热切换。 |
| 严格委派失败就停 | 上游 Skill 含必须真实 spawn 及不得静默回退要求。本版保留真实调用证据，但允许说明失败后由主线程继续可完成工作，避免工具故障让任务悬空。 |

这里采用的是任务分工思想和已核验的配置键；没有照搬上游安装器或 Skill 正文，也不导入其角色、权限设置和历史日志采集工具。

## 开关管理范围

| 配置键 | 开启值 | 关闭行为 |
| --- | --- | --- |
| model | gpt-6-astra | 恢复开启前值或原先未设置状态 |
| model_reasoning_effort | high | 同上；本机当前基线为 medium |
| agents.enabled | true | 恢复原值 |
| agents.max_concurrent_threads_per_session | 2 | 恢复原值；遇旧别名 max_threads 先停止，避免两个上限并存 |
| agents.default_subagent_model | gpt-5.6-luna | 恢复原值 |
| agents.default_subagent_reasoning_effort | medium | 恢复原值 |

另在全局 AGENTS.md 尾部加入两枚专用注释包围的模式规则。开关开启时，这段文字构成用户要求的按需委派规则，仍受平台和项目约束。关闭移除该块，原有“不主动委派”偏好恢复。

关闭不是“禁止所有 Agent”或切到另一个固定模型。其他工作流原来允许的子 Agent 不受此 Skill 强行禁止。

## 生效边界

1. **文件层**：脚本解析 TOML、修改并回读，状态显示配置是否保存及是否被手改。
2. **会话层**：全局默认供后续新会话/重启加载。已有会话可能仍保持原模型和旧规则；显式调用 Skill 可同步行为，但无法靠文字修改运行参数。
3. **配置覆盖层**：UI 选择、项目配置、profile、命令行和平台限制可能覆盖全局默认。脚本不枚举全部项目，也不会修改这些层；全局 AGENTS.override.md 非空时拒绝开启，避免保存无效规则。
4. **执行层**：只有实际 spawn 成功并显式选择 Luna，才能报告 Luna 参与。文章中“完全锁死”不是本设计承诺。

如果用户要求当前会话立即改到 Astra/high，而当前工具没有该能力，应说明需通过模型选择器或新会话加载；不能用修改 config.toml 后的状态截图当成实际会话参数证据。

## 成本与质量取舍

high 保留复杂推理质量空间，也可能比 medium/low 花更多额度。收益来自把可界定的执行任务交给 Luna、减少根线程读大文件、减少重复验证，而不是把主线程本身变便宜。

适合：多个互不重叠的模块修改、独立代码路径调查、批量结构化处理。通常不适合：一句文案、一处配置、小型问答、共享状态很强的连续调试。

主线程给简短契约，子任务报告关键证据，主线程整合而不重做。Luna 遇阻先缩小一次，仍失败接回主线程；不反复重启相同工作。风险高的决定依然由主线程处理，测试按实质风险选择。

## 状态与恢复设计

- `status` 只读；输出保存模式、六个默认值、冲突及重载说明，不输出全部配置。
- `on`/`off` 幂等；重复执行不覆盖原始基线、不重复插入规则。
- UTF-8（含/不含 BOM）与有 BOM 的 UTF-16 保留原编码。既有内容和混合换行不盲目转换；无期间改动时关闭恢复原始字节，原先不存在的文件恢复为不存在。
- 有期间改动时仅恢复自己管理的键并去掉受管块；MCP 等无关改动保留。受管键或受管块被手改则拒绝覆盖，要求先处理具体冲突。
- 切换使用排他锁、单文件原子替换和持久 pending 日志。两个文件无法同时原子提交，因此中断状态会如实暴露，`recover` 可回退记录内的 before/after 状态。
- 如果回滚时检测到新的用户修改，不自动覆盖。进程异常退出遗留的锁也不自动抢占；先核实没有运行中的切换进程再处理该锁。
- 并发 2 是已保存的 Codex 默认上限；当前平台是否加载、是否被覆盖仍需实际调用核验。禁止子 Agent 递归委派属于行为契约，不冒充代码层沙箱隔离。
- 配置或规则有期间修改时，只承诺受管值恢复和无关内容保留；不承诺整份文件字节还原。外部编辑器不共享本脚本的锁，脚本作写前冲突检查而不是声称能锁住所有编辑器。
- 原始字节备份仅位于 Codex home 的 quota-mode/backups，不自动清理，也不上传 GitHub。快照可能含用户原配置中的私有内容；脚本不会打印这些内容。

## 验证与使用

运行 `scripts/test_quota_mode.py` 使用隔离的临时 Codex home，不写真实全局配置。覆盖重复开关、原始字节恢复、中文/UTF-16/混合换行、无关改动保留、受管冲突拒绝、覆盖文件、缺失文件、旧配置别名、并发锁及失败恢复。

Skill 切换脚本要求 Python 3.11+；随附 tomlkit 0.15.1 及 MIT 许可证用于保留 TOML 格式，不需全局 pip 安装。技能结构另用 skill-creator 的 quick_validate.py 检查。测试通过不等于保证实际订阅额度节省。

本次 14 项自动测试通过；独立 Luna 在另一个隔离目录完成“开启→修改 MCP 与规则→关闭”的前向测试，验证修改保留。根据其反馈，状态输出改为 ASCII 转义 JSON，避免父进程用错误代码页解码中文；使用者解析后显示中文。实际当前模型切换、跨项目新会话加载和订阅额度收益未作实测，安装时不声称这些已通过。

用户只需说：

- 开启省额度模式
- 关闭省额度模式
- 查询省额度模式

新安装的 Skill 需要新会话发现；当前会话可直接读取安装路径执行。恢复未完成事务是维护动作，通过 `recover` 执行，不是日常第四个模式。
