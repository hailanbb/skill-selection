# 商业活动高管复盘报告制作指南 (Event Retrospective Report)

本 Skill 用于将线下商业推介会、会销签约会、招商巡回或行业峰会的现场数据与过程材料，提炼制作成专为手机端竖屏浏览（钉钉/微信）优化的高管复盘长网页（HTML）。

---

## 一、 输入数据与前期核对清单

启动制作前，优先向用户收集或在资料库中检索以下要素：
1. **活动基础信息**：日期、精确时间节点（签到/开场/晚宴/结束）、举办地点（具体酒楼/会场大厦与楼层）、活动全称；
2. **核心转化战报**：邀约报名数、实际到场数、现场签署意向书/协议数（或当场成交数）；
3. **现场热烈反响**：现场最打动客户的 2~3 个核心产品亮点、功能或商业方案；
4. **未当场签约客户关注点**：客户犹豫、观望的核心考量（需作婉转转化分析）；
5. **现场问题与反思**：开场节奏、设备运转、物料准备、嘉宾协同中的真实客观疏漏；
6. **团队亮点与表彰**：表现突出的讲者、新秀同仁姓名及具体亮点；
7. **现场实拍照片目录**：存放现场高清照片的本地路径（如 `01.jpg`、`02.jpg` 等）。

---

## 二、 八大标准汇报模块架构

报告严禁采用幻灯片 PPT 模式，必须采用**自上而下的长网页卡片流**结构：

```text
├── 模块一：封面与活动概览（时间节点、精确地点、专场定位）
├── 模块二：核心转化战报看板（3大核心指标卡：报名数、实到数、意向签约数与转化率）
├── 模块三：本次活动的核心战略意义（战略大盘首站、验证快速签约闭环、内振士气外树标杆）
├── 模块四：亮点表现与现场热烈反响（新秀表扬、反响最热烈的核心环节）
├── 模块五：高潜观望客户的核心关注与转化契机（婉转、客观、保护团队士气）
├── 模块六：现场问题反思与专题研讨安排（客观反思 + 会后组织团队专题研讨）
├── 模块七：中后台协同支持诉求（宏观赋能面：所见即所得、真实样板、OCR攻坚）
└── 模块八：下阶段推进方向（简明几句话） + 现场纪实剪影（纯净大图、Base64内嵌）
```

## 三、 高管视角沟通与表达红线准则

1. **结果三秒前置，不让高管找数据**：
   首屏以简洁有力的数字卡片展现到场率与转化率，红绿指标状态分明。
2. **剔除冗余测算与财务杂费**：
   商业方案只讲商业增收逻辑与投资回收体感，**严禁堆叠复杂的底层数学假设公式（如天数×单价×分润百分比）**；不主动罗列零散的会务杂费与单客获取成本（CAC），除非用户明确要求。
3. **呵护士气，婉转表达客户疑虑**：
   将未现场签约的客户定义为“具有极高潜力的储备客户群”，从技术采纳周期、客户审慎理性、政策信息差等客观规律切入，既客观呈现顾虑，又点明后续跟进转化的抓手，绝不挫伤一线销售士气。
4. **肯定新人，提振组织活力**：
   主动点名表扬首次登台担当核心演示与宣讲的新秀同仁，体现团队成长与准备充分度。
5. **现场问题客观陈述，不擅自预设解法**：
   坦诚列出开场迟到、设备瘫痪、翻页笔/签约笔缺失、讲稿现场打印等真实问题；但文末统一表述为“会后将统一安排相关团队召开专题研讨会，制定系统性改进措施”，体现组织严谨性。
6. **中后台诉求讲宏观面，不陷入微观抱怨**：
   聚焦展示产品所见即所得、跑通真实场景树立样板客户、核心难点（如纸质 OCR 识别）攻坚三大宏观维度，强化跨部门合力。
7. **下阶段推进简明有力**：
   用几句话明确销售团队将第一时间跟进回访，全力推进意向书向正式合约转化，不细分僵硬的小时/排期。

## 四、 视觉设计规范（XKONG 科技深蓝体系）

所有 HTML 页面必须严格遵循以下视觉基准：
- **配色系统**：
  - 页面背景：`#101924` 搭配渐变 `#17212D`；
  - 卡片容器：`#152438`，内衬背景 `#0E1A29`；
  - 边框强调：`rgba(7, 110, 225, 0.22)` 与高亮蓝 `rgba(7, 110, 225, 0.35)`；
  - 品牌主色：经典科技蓝 `#076EE1`；
  - 高光辅助：亮青色 `#00D2FF`、冰蓝色 `#EAF3FF`；
  - 达成标绿：`#10B981` / `#34D399`。
- **字体与语言**：
  - 字体：全页面强制使用**微软雅黑（Microsoft YaHei）**，严禁使用其他非标字体；
  - 语言：纯中文简体字，不添加多余的繁简切换按钮。
- **移动端交互**：
  - 响应式设计（手机端最大宽度 680px 居中）；
  - 底部配备悬浮快捷导航（概览、战报、战略、亮点、反思、协同、剪影），支持单手平滑滚动定位。

## 五、 现场照片 Base64 嵌入红线

为确保 HTML 文件发送到钉钉群后，任何员工或老板在手机上都能**零外链、脱机秒开大图**：
1. **严禁使用相对或绝对路径**（如 `src="照片/01.jpg"` 或 `src="E:\..."` 在移动端接收后必然裂开）；
2. **调用内置脚本处理照片**：
   ```bash
   python <skill_path>/scripts/embed_event_photos.py --photo-dir "<照片目录>" --html-path "<目标HTML路径>"
   ```
3. **处理要求**：
   - 自动按文件名序号升序排序（`01.jpg` -> `08.jpg`）；
   - 使用 `ImageOps.exif_transpose` 纠正手机拍照旋转角度；
   - 缩放至最大边 1200px、82% 质量 JPEG，内嵌 Base64 代码，控制单 HTML 文件大小在 1.5MB~2MB 之间；
   - **纯净实拍展示，图片下方不配置说明文字**。

## 六、 交付与质量自查清单

交付前检查：
- [ ] 核心战报指标（报名、实到、签约）是否准确醒目；
- [ ] 是否彻底删除了冗余的公式化基准假设与微观财务杂支；
- [ ] 50万增收方案是否通俗易懂，与前两项亮点排版对齐；
- [ ] 未签约客户顾虑是否措辞婉转、保护士气；
- [ ] 现场反思是否客观指出问题并承诺召开专题研讨；
- [ ] 中后台支持是否聚焦在“所见即所得、实体样板、OCR方案”等宏观面；
- [ ] 下阶段计划是否精炼阐述第一时间推进意向书转正；
- [ ] 字体是否全为微软雅黑，语言是否纯中文简体；
- [ ] 现场照片是否全额 Base64 内嵌且能脱机离线浏览；
- [ ] 图片下方是否干净无多余文字。
