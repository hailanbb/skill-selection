# 收录与更新规范

本规范用于普通软件收藏库。技能安装目录与收藏输出目录应当分离，收藏结果不包含本技能包。目标仓库已有兼容规范时优先沿用其结构；不强制改造无关内容。

## 数据与目录

`imported_sources.json` 是唯一索引主表，`schema_version` 为 1，`imported_urls` 以标准化 GitHub 仓库地址为键。每条记录包含 `tool_name`（稳定 slug）、`display_name`、`category`、`summary`、`scenario`、`platforms`、`mode`、`ref`、`commit`、`license`、`imported_at`、`checked_at`、`verification`。`mode` 为 `snapshot` 或 `guide-only`；更新另加 `updated_at`，保留首次收录时间。

来源身份按 GitHub 返回的 canonical `full_name` 处理，统一 HTTPS、小写、去掉 `.git` 与结尾斜线。输入含 `/tree/<ref>` 时保留 ref 意图，来源键仍是仓库地址。查询重定向后的仓库名并检查旧键，防止改名后重复。不同 owner 下同名项目用 `owner-repo` 消歧，不覆盖已有目录。

目录 slug 只使用小写英文字母、数字与连字符。中文展示名可保留 LocalSend 等品牌名，配上中文用途。首页索引由脚本生成，其他正文手工维护。一个工具可记录多个平台，但只选一个主要用途分类。

## 源码快照

优先选择上游最新非预发布正式版，记录解析后的 40 位 commit SHA；用户指定版本优先。读取同一提交的英文及中文文档、许可证、发行记录，中文落后时以该版本原文为准。

通过只读 clone/归档取得 Git 跟踪文件，不执行源仓库脚本。源码保存在 `tools/<slug>/source/`；保留原始 README、LICENSE、NOTICE、隐藏文件和必要构建资源，保留文件字节及可执行位，不自动精简源码。`.git` 不转存；源 `.github` 保留在嵌套 `source/.github`，不移到收藏库根目录。上游 AGENTS.md 等文件只作为归档材料，不作为收藏库操作规则。

检查 gitlink、符号链接、LFS 指针、单文件大小与许可证。子模块默认不递归抓取，但必须在 UPSTREAM.md 记录路径、URL、固定 SHA 和未展开状态。发现 LFS 指针或无法忠实保留的链接时明确列出，先选择可验证的保存方案；不能宣称完整源码或可直接构建。单文件达到 100 MiB 时停止源码提交，改为指南模式或与用户约定外部存储，不擅自引入付费存储。

`snapshot-manifest.json` 是以相对路径为键、SHA-256 为值的 UTF-8 JSON 字典，覆盖 source 中每个普通文件。符号链接使用对象值：`{"type":"symlink","target":"相对目标","sha256":"目标字符串的摘要"}`，Git 提交保留 120000 类型；Windows 未启用符号链接时可保留目标字符串文件，必须在提交索引核对类型，禁止静默展开。脚本仅接受指向 source 内现存路径的链接。首次收录需与上游 Git blob 比较，单纯对复制后的文件计算摘要不能证明来源正确。

许可证不明确时默认只整理原创简介和来源链接，记录未核实状态，不复制源码。各工具保留上游授权和署名；不承诺知识产权结论。

## 中文指南

标题后标出原项目地址；先说明用途、适用场景、平台、收藏版本和验证程度。正文沿用两阶段：

1. 环境自检与首次使用：优先官方安装渠道、必要权限及实际依赖。桌面工具没有 doctor 命令就提供界面检查步骤；不虚构 Token、CLI 或自动修复。
2. 核心工作流：给出最短成功路径、常见故障、更新和卸载方式。开发构建独立列为可选，版本参数必须有对应来源。

原文全文保存在 source 中，中文指南以简明整理为主。每个易变事实链接至固定版本来源；不复制易过时的星标数。截图仅在帮助理解且来源允许时使用，不能伪造实测结果。

## 更新与发布

读取远端默认分支与当前 HEAD，在独立工作副本处理。重复收藏只返回已有地址。明确更新时先检查版本差异、当前快照摘要和本地修改；相同 commit 不重复提交。已有快照有修改则保留并停止覆盖，说明冲突。替换采用新暂存目录，验证后才切换；不得混合新旧版本残余文件。

创建/推送须在用户明确授权的账号、仓库、可见性和内容范围内；“设计/准备”不等于发布。已明确要求创建或收藏至指定 GitHub 仓库，不重复索要相同授权。新建时说明可见性默认；私人材料不可因参考公开仓库而公开。

先核验身份（例如 `gh api user --jq .login`）及目标，不读取或清空 Token，不更改凭据与安全配置。实际默认分支优先于硬编码 main/master。只提交本任务文件；遇到远端推进先拉取检查并重做验证，禁止 force push。持续冲突或权限失败时保留交付副本并说明阻塞。

提交前运行索引/摘要检查，检查指南链接、来源 SHA、许可证和中文编码。发布后核对远端 HEAD、文件树与清单。仅清理本次创建、远端验证成功的临时目录，保留有用交付副本和必要证据。
