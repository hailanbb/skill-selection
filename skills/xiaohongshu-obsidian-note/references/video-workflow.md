# 视频处理与清理：沿用抖音转笔记的方法

识别为视频，或 LIVE/混合笔记中的动态片段承载关键知识时，读取本文件。这里完整保留抖音技能的证据流程，不要求另一项技能已安装；不同平台只替换合法取材方式。视频的最终产物仍然是提炼后的 Markdown 与真实关键图片，不是视频备份包。

## 1. 复用材料，再补口播证据

先完成首次配置，再创建 `run_workspace.py create` 返回的运行目录。按以下顺序取材，已有合法材料不重复下载或转写：

1. 用户提供、能确认属于该原帖的本地视频、SRT/VTT/TXT 或 ASR 结果；复制到运行目录，不移动原件。
2. 当前小红书原帖的作者、标题、可确认发布时间、简介和可用独立字幕轨。
3. 本机已有的中文 ASR 或客户端音视频理解能力。若已装 `dy-note` 且其本地转写接口适用，可只复用本地文件转写能力；先查该接口文档，把输出目录指向本次运行目录，不把小红书链接传给抖音提取器。
4. 视频画面、烧录字幕和必要的图像文字识别。网页简介不是口播逐字稿；ASR不能证明画面上的数字、价格、菜单和动作。

缺少可靠口播证据时，明确使用 `visual_only`，只写已核实的画面及原帖正文，不补写没听到的内容。云端转写会上传视频/音频，使用前须取得相应授权；不默认安装新模型或购买服务。

视频下载与权限边界遵循 [浏览器取证流程](browser-workflow.md)。不假设 yt-dlp 支持小红书，不猜测 CDN 地址，不绕过验证码或登录限制。

## 2. 结合内容筛关键画面

确认实际时长，先均匀抽取约 12–24 张候选，或根据字幕段落直接定位关键时刻。以下 `PYTHON`、`SKILL`、`RUN` 均替换为实际启动器/绝对路径，不是需要展开的环境变量：

```text
PYTHON -X utf8 "SKILL/scripts/extract_keyframes.py" --video "RUN/source.mp4" --out-dir "RUN/candidates" --auto-count 16
PYTHON -X utf8 "SKILL/scripts/extract_keyframes.py" --video "RUN/source.mp4" --out-dir "RUN/selected" --at 00:03.5 --at 00:27 --at 01:12
```

逐张查看并联系相邻口播/章节，通常精选 3–8 张：优先概念示意、具体步骤、操作界面、表格、关键动作、前后对比和结果。去掉黑屏、片头片尾、广告、重复构图、无关人物、模糊转场及遮挡文字的帧；相似画面保留更清楚的一张。

数量不是硬配额。纯口播可能只需少量真实画面，多步骤教程可增加；不要为凑数加入装饰图。均匀候选不等于看完视频，快速步骤须回到对应时间补帧。沿用抖音的选图逻辑，但小红书字密集的画面优先清晰度，不强制压至 640；确实可读时再用 `--frame-width 640`。

## 3. 写作与验证

确认每项结论有口播、原帖正文或已看画面支持，每个视觉说明有对应帧。专名、数字和价格结合证据纠错，仍存疑则标明。按知识点提炼，不按每句口播堆时间轴，也不写完整逐字稿、自检清单或自测题。

按 [输入约定](input-contract.md) 填写 `video_duration_seconds`、真实 `timestamp_seconds`、`content_basis` 及 `video_reviewed_to_end`，使用本技能的 `{{image:N}}` 与 evidence.json 发布接口，**不要照抄抖音版的发布参数或占位符语法**。发布后运行 `validate_note.py`，实际查看最终图片，确保说明附近的截图可读、链接可用。

## 4. 必须执行的清理收尾

把本次下载、音频、转写、候选帧、辅助 JSON、临时脚本、状态和日志全部限定在 `RUN` 内。外部 ASR/下载程序应同时显式设置输出目录与子进程工作目录；支持时把本次临时缓存指向 `RUN/cache`。既有模型和用户依赖缓存可以复用，不属于要删除的临时产物。

成功、失败或可正常处理的中断均进入收尾：

1. 停止并等待**本次**下载、抽帧、转写子进程退出，关闭本次文件句柄，不终止用户其它任务。
2. 若终端仍位于 `RUN`，先切换到它之外的已存在安全目录。清理脚本保护当前工作目录，不应从待删除目录内调用。
3. 以脚本绝对路径调用 `PYTHON -X utf8 "SKILL/scripts/run_workspace.py" cleanup --path "RUN"`。
4. 核对 `cleaned: true`、目录确已消失，并检查本次记录的项目工作目录散落文件。只清理由本次创建且明确可丢弃的具体文件，不用 `*.mp4`、`*.json` 或递归清空项目目录的做法。
5. 交付时说明清理结果。发布成功后仅留最终 MD、被引用图片和配置；用户原始视频、既有笔记/图片不删除。失败没有成品，也仍需清理临时取材。

强制杀进程或断电不能保证收尾立即执行；恢复后只处理有匹配标记的本次目录。文件被占用或权限阻止清理时，报告残留绝对路径和原因，不把失败描述为“已清理”。只有用户明确要求保留续作才例外保留临时材料并说明位置。
