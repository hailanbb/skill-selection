# 小红书转笔记

把你发给 AI Agent 的一条小红书链接，整理为适合复习的 **Obsidian Markdown 图文学习笔记**，并把相关真实图片保存在自己的库里。支持图文、多图、LIVE 图文和视频；既不只摘标题，也不把全部字幕直接塞进笔记。

这是一个可迁移的 Agent Skill：`SKILL.md` 指导 Agent 读内容、分析和选图，独立 Python 脚本负责配置、图片处理、去重、保存和清理。不是浏览器插件，也不是无需登录即可下载所有小红书内容的爬虫。

> 入口是你主动发送的**具体笔记链接或分享文本**。本技能不收集收藏夹、不扫描个人主页、不监控账户，不保存开发时用于观察内容类型的收藏地址。

## 你会得到什么

通常得到一篇 `.md` 笔记和数张本地图片：

```text
你的 Obsidian 库/
├── .obsidian/
├── 01 待阅收件箱/
│   └── 番茄盆栽的浇水判断与光照安排.md
└── 附件/小红书/
    ├── <32位内容哈希>_0.png
    └── <32位内容哈希>_0.png
```

正文由内容决定，可以是知识讲解、操作步骤、图文对照或地点信息表。图片放在相应解释附近，有明确图注；保存原作者、规范化来源链接和日期，不凭空补充原帖没有的信息。

| 输入类型 | 处理方式 | 图片策略 |
| :--- | :--- | :--- |
| 图文 / 多图 | 阅读正文，按原顺序查看所有图片后提炼知识 | 优先取实际可获得的大图，默认保留像素尺寸；知识卡片不统一缩至 640 |
| LIVE 图文 | 按图文识别，关键知识依赖动态时额外查看动态片段 | 保留真实静态图或动态关键帧，不因 LIVE 标记把整篇误判成视频 |
| 视频 | 字幕/ASR或音视频理解与画面结合，分析后选择关键帧 | 按知识点选清晰画面，必要时精确时间补帧，不用封面代替完整内容 |
| 短链接 / 分享文本 | 先在授权浏览器中打开，确认最终具体笔记 | 后续按真实媒体类型处理，不猜笔记 ID |
| 主页 / 收藏夹 | 提示提供具体笔记链接 | 不采集、不建立收藏抓取任务 |

不输出完整逐字稿、全文字幕、可迁移自检清单、AI 自测题、任务复选框或残留视频文件。字幕/ASR如果使用，只是临时证据，完成后删除。

## 快速开始：只需做三件事

### 1. 把完整技能文件夹放进客户端技能目录

复制本目录 **`xiaohongshu-obsidian-note` 整个文件夹**，不要只复制 `SKILL.md`，也不要把整个仓库当一项技能安装。

Antigravity IDE 的项目级示例：

```text
你的项目/
└── .agents/skills/xiaohongshu-obsidian-note/
    ├── SKILL.md
    ├── README.md
    ├── scripts/
    ├── references/
    ├── requirements.txt
    └── agents/
```

Antigravity IDE 当前官方文档列出的全局位置是 `~/.gemini/config/skills/<技能目录>/`，项目位置是 `<项目>/.agents/skills/<技能目录>/`。安装后重新打开会话，确认客户端已发现技能。[官方 Skills 文档](https://antigravity.google/docs/skills/)

**关于 Antigravity 2.11.0：**本技能采用标准目录、YAML 前言和本地脚本，不依赖特定客户端工具名称；但没有在该精确版本中完成端到端验收，不能把结构兼容当成实测通过。若该版本设置页采用不同技能位置，以该版本实际配置为准；IDE 和 CLI 的安装规则也不能混用。

其它通用 Agent：使用其文档指定的技能目录。如果客户端不自动发现 Skill，可把本 `SKILL.md` 的绝对路径交给它，并要求先完整读取，再按相对路径访问脚本。**目录被识别不等于具备浏览器、图像理解或本地写文件能力。**纯聊天、没有本地文件权限的客户端不能直接写你的 Obsidian 库。

`agents/openai.yaml` 仅提供可选展示元数据；其它客户端可以忽略，不影响工作流。无需安装 `douyin-obsidian-note` 或 Agent Reach 才能使用。

### 2. 准备能力与依赖

| 能力 / 工具 | 是否必要 | 作用 |
| :--- | :--- | :--- |
| Python 3.10+ | 必要 | 配置、保存、校验、清理；可使用客户端能发现的普通 Python |
| Pillow | 必要 | 验证真实图片、保留可读尺寸、去除 EXIF/GPS、计算内容文件名 |
| 能访问原帖的浏览器或连接器 | 在线链接处理必要 | 使用你已授权的会话，获取真实正文和媒体 |
| 图像理解/看图工具 | 必要 | 阅读知识卡片、判断画面与正文的对应关系 |
| ffmpeg + ffprobe | 本地视频抽帧必要 | 校验视频时长，提取候选和指定时间帧 |
| 原字幕 / ASR / 音视频理解 | 完整口播分析必要 | 支撑视频里的口述事实；缺失时只做明确标注的视觉笔记 |
| Obsidian 本体 | 已有库必要；保存时无需保持打开 | 库根需存在 `.obsidian`，最终可在 Obsidian 查阅 |

脚本不捆绑大模型，不要求某品牌 API Key，不硬编码开发者 Python/浏览器路径，不自动导出 Cookie，不安装全局依赖。Agent 应先检测，缺什么说明什么。

已能在终端使用 `python` 时，可在本技能目录运行：

```text
python -X utf8 scripts/doctor.py
```

若缺 Pillow，可在你选择的 Python 环境或虚拟环境中安装：

```text
python -m pip install -r requirements.txt
```

有多套 Python 时，两条命令必须使用同一个解释器；Windows 也可用已经确认有效的 `py -3` 或可执行文件完整路径。ffmpeg/ffprobe 由用户或客户端按所在系统提供，不能假定装了 Python 包就拥有这些程序。

没有浏览器访问能力时，可提供合法保存的原帖图片、视频和具体来源链接，但仍需要图像理解与文件权限。没有字幕/ASR又不能听懂视频时，只允许明示“未核实口播”的视觉笔记，不宣称完整理解。

### 3. 发链接，首次填写两个路径

你可以直接对 Agent 说：

> 使用“小红书转笔记”，把下面这条小红书笔记整理成带原图或关键截图的 Obsidian 学习笔记：［粘贴链接或完整分享文本］。

第一次运行，Agent 会问：

> 请提供保存 Markdown 笔记的文件夹完整路径，以及保存图片的文件夹完整路径；两者需在同一个 Obsidian 库内。

例如你可以回答（只是路径结构示例，不是默认值）：

```text
笔记目录：D:\知识库\01 待阅收件箱
图片目录：D:\知识库\附件\小红书
```

脚本会向上寻找 `.obsidian` 判断库根。两个目录可以不同，但必须同库；中文、空格、`&`、单引号正常支持。输出目录在库内的相对部分不能包含 `[]|#` 等 Obsidian 嵌入分隔符，遇到会提示修改，而不是产生失效图片链接。

配置保存在你本机 `~/.config/xiaohongshu-obsidian-note/config.json`，不会写入技能包。后续通常不用再问；目录移动、库丢失或切换库时重新配置。它不会偷用抖音技能的旧路径。

## 常用说法

**图文教程**

> 把这条小红书做成学习笔记，逐张看图，保留文字能看清的知识卡片，按步骤整理：［链接］

**视频**

> 分析这条小红书视频，把关键步骤和对应画面保存到 Obsidian，不要完整逐字稿：［链接］

视频分支采用“抖音转笔记”的处理方式：复用已有素材，核实字幕/口播，结合内容筛选关键帧，再提炼为带对应画面的笔记；具体见 [视频处理与清理](references/video-workflow.md)。不直接套用抖音下载器，也不要求安装抖音技能。无论成功或失败，最后都清理本次工作目录里的视频、音频、转写、候选图、辅助 JSON 和日志；只保留最终笔记与引用图片，不删除你的原始文件。

**分享文本**

> 下面是小红书复制出来的整段分享内容，请识别其中的链接并转为图文笔记：［分享文本］

**本地素材补充**

> 这条原帖链接目前打开不了，我已保存图片/视频到［目录］。请仅用这些材料整理，标出没法核实的部分，不删除我的原文件：［原帖链接］

**更换位置**

> 小红书笔记以后保存到［新的笔记目录］，图片保存到［新的图片目录］。请更新本技能配置。

**重复链接**

同一笔记即使分享签名、标题或文件名变了，也优先按原帖 ID 识别已归档文件并跳过。默认不覆盖旧笔记。查重范围为配置的笔记目录及子目录；如果你把旧笔记移到范围之外，需要明确扩大查找位置，不能承诺全库自动去重。

## 保存格式与高清图片

八个笔记属性：`title`、`category`、`url`、`origin`、`cover`、`author`、`publishTime`、`createTime`。与抖音转笔记保持键名一致，`origin` 改为“小红书”，分类区分图文、视频和混合媒体。未知发布时间留空，“编辑于昨天”不能冒充发布时间。

最终来源为不带访问签名的原帖链接。浏览时所需的完整分享链接只用于临时访问，不把 `xsec_token` 写进最终笔记。原帖之后可能删除或需要重新登录，所以图片保存在本地；来源链接仍用于归属和追溯，不保证永远可打开。

图片命名采用 `<32位MD5>_<尺寸标记>.<扩展名>`，MD5仅用于内容去重，不用于安全认证。默认 `_0.png` 保留当前素材像素尺寸、去除元数据；视频可选择 `_640.jpg` / `_1280.jpg` / `_1920.jpg`。文字图不统一压小，也不会用 AI 生成图冒充原图。相同最终图片内容可以复用已有文件。

Obsidian 用 `![[库内相对路径]]` 嵌入图像。**MD 与图片是两类文件**，迁移时必须一起带走；在不支持 Wiki 图片链接的普通 Markdown 阅读器里，需要先转换链接。具体模板见 [笔记规范](references/note-format.md)。

## 从链接到笔记的执行流程

1. 检查客户端能力、依赖和首次路径配置。
2. 从用户本次输入识别具体笔记；短链在授权浏览器解析，主页/收藏页拒绝作为采集入口。
3. 核对原帖 ID，检查是否已保存。
4. 创建带标记的独立临时目录，获取正文、可确认元数据和真实媒体。
5. 图文逐页核对，视频结合口播证据和关键画面，分析后精选入笔记的图片。
6. 生成只含正文的草稿与取证 JSON，检查覆盖范围和图片可读性。
7. 脚本保存图片、写八个属性、替换图片占位符、原子提交新笔记，不覆盖旧文件。
8. 验证中文、属性和链接，实际检查保存后的图片；清理此次视频、音频、转写、未选图、草稿及签名资料。

工作流涉及的所有程序均可使用参数数组运行，不要求嵌套 PowerShell 字符串或后台环境变量。详细字段与命令见 [脚本输入约定](references/input-contract.md)；浏览器适配与媒体判断见 [取证流程](references/browser-workflow.md)。

## 安全边界与失败处理

- 只访问你指定的原帖，不修改账号、不收集评论者信息，不扫描你的收藏。
- 登录失效、验证码、无权访问、内容删除时停止取证；请你正常登录或提供已有素材。不会通过 Cookie 导出、伪造签名、绕过验证继续。
- 原图缺页、视频未查看完整时默认不发布。确实需要局部笔记，须你明确接受，且正文标出覆盖范围与原因。没有任何可用真实图片时不会伪造“图文笔记”。
- 发布中途失败会回滚本次新增附件，不删除已复用的图片，不覆盖用户现有文件。默认发布只支持有硬链接能力的文件系统；某些网盘挂载和 exFAT 会安全失败。
- 临时清理只接受本技能创建且路径标记匹配的目录，不对库根、整个下载目录或用户原始文件做删除。
- 强制终止或断电可能留下工作区、临时 MD 或发布锁，恢复时需核对具体路径与进程归属，不能承诺崩溃时也必然即时清理。
- 本地保存仅面向用户有权访问内容的个人查阅学习。保留归属，不默认许可批量再发布原作者图片。

## 常见问题

**为什么不直接分析收藏夹？** 这是“用户发一条链接，处理这一条”的技能；收藏夹不是长期数据源。传入主页/收藏页会提示提供具体笔记。

**图片很多，会不会只看前几张？** 不会默认只看前几张。必须确认原帖图数与已查看页码；每张独立知识卡片都要纳入理解，需要时全部保存。只可省略不承载新信息的重复或装饰图。

**页面有 LIVE，是不是就按视频处理？** 不是。判断依据是当前笔记结构，而不是页面出现视频元素或下载插件显示的视频数量。LIVE 关键动态内容需额外核实。

**能否不装 ASR？** 可以。图文不需要；视频有原字幕或客户端音视频理解时也不必另装。只有画面证据时明确标为视觉笔记，不能补写没听到的内容。

**能否只保存标题和封面？** 这不足以实现本技能的学习笔记目标。若访问限制导致只能获取封面，须说明阻碍，不宣称已完成图文分析。

**为什么图片都在本地、不是原 CDN 外链？** 为防止签名过期、原帖删除或网络不可用后无法查阅。最终笔记链接到自己的库内图片。

**程序说图片不是有效格式？** 可能保存到的是登录页/错误页、未支持的动画，或扩展名与实际内容不符。重新获取合法静态图片，不只改扩展名。

**提示发布锁存在？** 可能另一项任务正在写入，也可能是异常中断残留。先核查，不能自动删除不明锁后并发写库。

## 开发验证与兼容性边界

在技能目录运行：

```text
python -m pip install -r requirements-dev.txt
python -X utf8 -m unittest discover -s tests -v
```

测试使用虚构 ID、合成图片与一次性测试库，不访问任何个人收藏，也不写真实 Obsidian 库。覆盖链接分类、签名去除、中文/空格/特殊字符路径、属性回读、高清图尺寸、视频帧缩放、重复来源、同名不覆盖、无效图片、漏图阻止发布、故障回滚和受保护清理。

当前验证层次需严格区分：

- Windows 本地：Python 3.12 下 36 项自动测试通过，包括成功发布与失败后的临时素材清理、成品及用户原始视频保护；Windows PowerShell 5.1 与 PowerShell 7.6 启动也已验证。覆盖脚本图文/视频帧发布链路与 UTF-8/YAML 回读，没有把真实私人笔记写入用户库。测试没有更改 PowerShell 执行策略，也不要求运行 `.ps1` 文件。
- 已登录 Chrome：查看图文及视频样本，验证多图/LIVE、正文和播放器的识别设计；**没有据此宣称实际原图下载、ASR、完整转存均已验证**。
- Antigravity 2.11.0、其它客户端、macOS/Linux：采用无私有工具依赖的接口与参数化脚本；未经目标客户端端到端运行的部分仍需当地验收。客户端应完成“发现技能 → 首次配置 → 用户发链接 → 取得媒体 → 看图分析 → 发布 → 清理”的实际流程，不能只看 `doctor` 通过。

仓库附带 Windows/macOS/Linux × Python 3.10/3.12 的 GitHub Actions 离线测试矩阵；新增配置需提交后由 GitHub 实际运行，不能将配置文件的存在当作已通过。离线测试不验证小红书线上访问、真实 ASR 或客户端交互。当前开发运行环境未发现 ffmpeg/ffprobe，因此真实视频解码抽帧仍需在已安装它们的目标环境验收。

## 来源与设计关系

继承同仓库 [抖音转笔记](../douyin-obsidian-note/README.md) 的 Markdown 属性、图片哈希命名与安全工作区实现；抖音版的上游设计参考 [Rimagination/dy-note](https://github.com/Rimagination/dy-note)。本技能独立适配小红书图文、LIVE、视频和访问边界，不复用抖音解析器，不要求安装抖音技能。Antigravity 安装位置依据 [官方技能文档](https://antigravity.google/docs/skills/)，不是依赖开发机器路径。
