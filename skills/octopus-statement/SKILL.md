# 八达通详单

## 已确认的默认行为

- 每张图独立处理。保留原图，不覆盖已有交付物，不自动合并历史详单。
- 从自上而下第一笔“交通费用补贴／交通費用補貼”开始，裁去该笔及下方全部内容。没有补贴记录时保留全图。用户另行指定的边界优先；“序号 N 以下”默认保留 N，不含 N 本身。
- 图片只作原像素裁剪，保留裁剪范围内的“+”交易，不改写交易或余额。
- Excel 排除裁剪范围内所有“+”交易，不限于增值。保留负数和零金额记录。不要把零、未知金额和正数混为一类。
- 列为：序号、日期时间、交易方、交易类别、金额（HKD）；信息缺失时增加备注列。序号从 1 连续编号，不把旧序号或表格行号当成新序号。
- 所有单元格水平及垂直居中，清晰表头、合适列宽、金额格式、筛选；**不冻结表头或列**。包含笔数和消费合计，汇总使用公式。
- 默认在原图所在目录的 `八达通详单_<原图文件名>/` 内保存 `<原图文件名>_裁剪后.png` 和同名 `.xlsx`。已有同名输出时选择新的编号目录，不覆盖。

## 执行

1. 定位用户指定的本地文件，查看图片。长截图分段查看并留少量重叠；记录坐标必须换回原图像素，避免重叠段重复录入。原图账户信息仅用于本次本地交付，不写进技能源码或上传外部服务。
2. 找出第一笔补贴记录的上方分隔线，并在此结束图像。核对最后一笔保留记录和第一笔排除记录。不能确定边界时先检查相邻原图区域；仍无法判断才询问，不猜测。
3. 逐笔提取日期时间、交易方、原始带符号金额及原图上下边界。金额精度保留原图小数位；日期时间按图片字面录入，不做时区换算。交易方保留源文字。图片中没有年份时不得从文件名直接补造年份。
4. 采用本技能的确定性脚本精确裁剪。调用前读取 [输入格式与使用说明](README.md#脚本输入)。`scripts/prepare.py` 只接收人工／视觉识别复核后的结构化记录，不自称具备 OCR 能力；它核对边界、过滤正数、保留缺失标记并给出独立汇总。使用当前环境获准的 Python 与 Pillow，不静默安装依赖。
5. 使用环境可用的表格技能及其指定运行时。Codex 文件工作流使用 `scripts/write_workbook.mjs` 和运行时提供的 `@oai/artifact-tool`，不搜索或读取包内部实现。将该脚本复制至本次可写工作目录，在该目录按表格技能建立到运行时依赖的 `node_modules` 链接；不要修改技能目录或依赖目录。遵守表格技能的操作标记、导出、检查及引用约定。
6. 复核截图与表格：所有保留交易逐笔核对，尤其正负号、小数、相同时间的不同交易与分段交界。金额或日期模糊／截断时留空，并写明缺失；未知金额不计入已知金额合计，同时清楚显示未识别金额笔数。无法判断金额符号的记录标为待核对，不能悄悄视作消费。
7. 检查裁剪边界、裁剪图像素一致性、记录笔数、独立金额合计、首末日期、公式错误、居中和无冻结。至少查看一张覆盖表头与数据的 Excel 渲染图以及裁剪图底部。导出成功不等于校验通过。

## 交付

给出裁剪图和 Excel 的本地链接，简述笔数、消费合计及确实存在的缺失。图片范围和 Excel 范围不同：图内正数交易仍可见，Excel 已排除。没有用户另行授权时，不发布图片、记录或工作簿到 GitHub／其他外部平台。
