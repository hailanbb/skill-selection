# Markdown 图文笔记规范

## 属性与文件

两个平台统一使用八个属性键。脚本用 JSON 引号编码 YAML 字符串，显式 UTF-8 无 BOM：

```yaml
---
title: "番茄盆栽的浇水判断与光照安排"
category: "小红书图文笔记"
url: "https://www.xiaohongshu.com/explore/0123456789abcdef01234567"
origin: "小红书"
cover: "附件/小红书/图片内容哈希_0.png"
author: "示例作者"
publishTime: ""
createTime: "2026-09-05 12:00:00"
---
```

示例 ID、作者和路径均为虚构，不是待处理链接。`publishTime` 仅填写原帖可核实完整日期，否则空字符串。小红书分类分图文、视频、混合三种，抖音为视频；`origin` 必须与 URL 平台一致。这不是对用户整个库的分类重构。

- 文件名由内容主题产生：保留中文、字母数字、下划线/连字符，过滤 Windows 非法字符和保留名，最长 56 字符。不同原帖同名时追加完整笔记 ID；同原帖换标题或访问签名也按 ID 跳过，不覆盖。
- 图片沿用“32 位内容哈希 + 分辨率标记”的命名。默认 `<md5>_0.png`：保留所取图片的像素尺寸，重编码为 PNG 去除 EXIF/GPS 等元数据；它**不是承诺拿到原帖最高分辨率**。视频可指定 640/1280/1920 宽度预算，生成 `<md5>_640.jpg` 等，绝不放大。
- 字多的图文必须以可读为先，默认不缩图；`_640` 仅在确认细节仍清晰时使用。PNG 可能比原 JPEG 占用更多空间，这是默认对文字保真的取舍。
- 图片链接使用库根相对 `![[附件/小红书/<hash>_0.png]]`。复制笔记到库外时需要连同图片迁移并转换链接；不能宣传单个 MD 天然包含二进制图片。

## 分析质量

开头简述“原帖解决什么问题、适用条件是什么”。按主题组织关键结论、步骤、参数、例子或对照。旅游/探店适合“地点—原帖推荐理由—可确认细节”的表格；教程适合带截图的步骤；观点帖须区分作者观点与事实，不强套同一模板。

把图片放在支持的说明附近，并给具体图注。所有入选图都必须在正文使用，不允许未引用图片堆积为附件。只有装饰/重复画面可以省略；18 张独立知识卡片不能只看前 3 张就宣称总结完整。高风险或时效性建议注明是原帖当时内容，不能把作者经验写成已验证专业结论。

不输出完整逐字稿、全文字幕、AI 添加的可迁移自检清单、任务复选框、自测题或通用套话。原帖本身是清单时可提炼其事实条目，但不转为要求用户执行/打勾的自检清单。不得留视频、音频、转写 JSON、下载签名或外链图片。原作者、原帖链接、真实水印需保留。

## 不完整与真实性

- 小红书图文必须核对全部原图；选图数量不等于查看数量。缺页默认阻止发布，只有用户明确接受局部材料才加 `--allow-partial`，并在笔记中显示缺页数量/原因。
- 视频必须依据实际完整查看来填写 `video_reviewed_to_end`；抽样截图本身不代表看完。`visual_only` 会自动添加“未核实口播”说明。
- 未核实的信息不猜。无法取得任何可用真实图片时不产出伪图文笔记，也不生成 AI 图片冒充原图。
- 最终检查图片打开后是否可读、裁切是否完整，以及说明是否与画面一致。语法验证、布尔字段和 exit code 均不能替代模型的视觉/内容审核。
