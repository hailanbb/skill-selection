# 存储设计与路径选择

## 路径必须来自首次使用的回答

首次实际归档没有有效本地配置时，询问用户“你希望把归档内容保存到 Obsidian 的哪个文件夹？请给我完整路径。”不在通用技能中预填私人路径，也不从本文件的示例自动启用路径。

用户回答后，识别库根并校验目标归属，将库根绝对路径 `vault_root` 和库内相对目录 `archive_root` 保存到本技能的共享本机配置。配置缺失才初始化；仅用户明确要求变更时替换配置。目标子目录不必预先存在，正式归档时自动按需创建；根库不存在时需先解决定位，不能擅自新建一个“主库”。

本机配置位置、读写工具、单次覆盖方式见 [runtime.md](runtime.md)。无需把私人配置装入技能包；同一台机器上有权限的其他 Agent 读同一 JSON 即可。

## 为什么建议独立的任务与经验区

分析典型分层库时，应区分待阅收件箱、源文件备份、只读来源、来源编译 Wiki、业务资料与平台资料。任务交接属于个人实践记录：直接放收件箱容易被误当成待加工剪藏，放只读来源或 Wiki 可能不符合其来源约束，放单一 AI 平台目录则不利于跨平台/跨领域复用。

因此可在首次用户需要建议时推荐独立的 `任务与经验/`；有编号的库可以选未占用编号。用户的实际回答优先，不能因为推荐路径缺失而要求提前手工建目录，也不擅自修改其分类规则。原有的项目复盘仍保留在原处，按需从新页链接，不批量迁移。

## 自动组织

```text
用户选定的归档目录/
  会话/YYYY/MM/YYYYMMDD-HHmmss-任务短名-唯一后缀.md
  经验/决策/YYYYMMDD-主题-唯一后缀.md
  经验/提示词/YYYYMMDD-主题-唯一后缀.md
  经验/代码/YYYYMMDD-主题-唯一后缀.md
  经验/避坑/YYYYMMDD-主题-唯一后缀.md
```

只建有内容的目录，通常每次一份交接快照。单条经验可只建经验卡并写足来源，不为套结构制造空页。领域用 `domain`、`project` 和 tags 区分；已有 category 规范适用时选择匹配类别，没有可确认匹配且字段非必填则省略，不发明分类。若库明确要求每页分类且无法匹配，才询问必要决定。

首次保存任务生成稳定 `task_id`；每页生成独立 `id`。后续相同任务沿用 task_id，不能只凭标题相同认定同一任务。日期带时区；文件名不用冒号与 Windows 非法字符，标题简洁，后缀用于避免冲突。Agent 内部自动处理新草稿重名，不为选后缀打断用户。

双链使用库根相对路径、不含 .md；展示名可加别名。只连已有页或本批会创建的页，缺少可靠目标则用纯文本，不创建无意义占位页。前后快照用新页里的 `previous`/`supersedes` 与双链串联，旧页不追加回链。

无需可变首页、全局索引、Dataview 或向量服务。检索工具读取保存区的元数据形成即时候选，按需再深读；避坑清单可通过 type=lesson 和 tags 查询聚合。用户要求汇总时可生成带日期的新汇总快照，不覆盖现有清单。
