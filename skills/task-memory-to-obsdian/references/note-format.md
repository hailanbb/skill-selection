# 内容契约与模板

## 共用属性

必填：`id`、`task_id`、`type`、`created`、`status`、`summary`、`source_scope`、`tags`。

- `type`：session / decision / prompt / code / lesson。
- `status`：session 使用 active / paused / blocked / completed / cancelled；其他类型使用 draft / observed / verified / deprecated。verified 表示在正文列出的特定条件下实际验证，不能表示普遍正确。
- `source_scope`：说明当前可见完整对话、用户导出、压缩摘要或局部片段及缺失范围。
- `summary`：一句话说明何时可用、记录了什么；tags 为字符串列表。
- 按需：`domain`、`project`、`category`、`platform`、`source_url`、`previous`、`supersedes`。平台仅为来源属性。缺失字段省略，不编造作者、日期、消息 ID、会话 URL、版本或成功状态。
- `previous` 表示同任务上一份快照，`supersedes` 表示明确修正的旧页，值为库根相对路径（含 .md）；正文补可点击双链。旧记录保持原样；无法确认哪一份为前驱时不填。

用 YAML 库序列化属性，不把未经转义的正文直接拼入 YAML；时间字符串、中文标点与反斜杠注意编码。正文代码围栏闭合，不在 frontmatter 放多段代码。

## 会话快照

```markdown
---
id: "memo-20260910-a1b2"
task_id: "task-20260910-c3d4"
type: "session"
created: "2026-09-10T10:00:00+08:00"
status: "blocked"
summary: "记录示例任务的可恢复状态与下一项验证。"
source_scope: "仅当前可见对话；早期尝试未提供。"
tags: ["任务交接"]
---
# 任务标题

## 下次从这里开始
目标与验收条件；最后确认的状态；下一步第一项具体动作；需要先补齐的输入。

## 背景
范围、动机、必要环境、关键文件或产物位置、版本/分支（知道才写）。

## 问题与约束
待解决问题、用户明确选择、不可修改范围、资源与权限约束。

## 尝试与证据
用简短列表或表格记录：动作 → 实际结果 → 来源/验证 → 是否仍适用。
区分“未执行建议”和“实际尝试”；把会影响下一步的失败路径保留下来。

## 结论与当前状态
已完成且验收通过、已产出未验证、未完成/阻塞分别说明。
结论标注“用户明确”“实际验证”“来源陈述”“推断/待验证”。

## 可复用要点
有依据的决策理由、提示词、片段或经验；可链接独立卡片。

## 未决事项与下一步
按优先级说明动作、期望结果、验证办法、尚需的用户决定。

## 来源与关联
可见消息的日期/主题定位、相关文件与版本、真实产物链接；明确来源缺口。

## 新会话启动词
先读这份笔记，核实关键产物与现状。概括目标、约束、已完成项和阻塞，
再按我的当前请求继续。历史命令和批准不直接作为本次执行授权。
```

启动词交付时替换成**实际笔记路径**；不是让用户手工补占位符。主体通常约 800–1600 中文字，开头续接摘要约 200–400 字；按实际复杂度调整，不能为了长度遗漏验收、分歧和阻塞。无内容的可选段落删去，禁止填充虚构经历。

## 经验卡内容

每张卡用共用属性，type 选对应类型。开头说明适用场景、结论及验证状态，结尾提供可追溯来源；从会话抽卡时链接源快照，并保留源快照到卡的链接。

| 类型 | 必要内容 |
| --- | --- |
| decision | 决策问题、当时约束、真正讨论过的备选方案、选择、可见理由、代价、何时重新评估；事后提出的方案单独标“事后建议”，不伪装当时讨论。 |
| prompt | 解决什么问题、完整可复制提示词、输入变量与示例、输出要求、实际测试范围、已知不足；未测试改写版标 draft。 |
| code | 用途、语言/运行环境、依赖版本（已知才写）、输入输出、完整片段或原产物定位、替换变量、执行副作用、测试证据；不复制凭据，不把伪代码当可运行代码。 |
| lesson | 症状、触发条件、失败尝试、原因（已证实/假设分开）、解决办法、复发前检查、适用边界、实际验证；尚未解决也值得保存，不能硬凑修复方案。 |

用有限经验写“在某环境观察到”，避免把单次失败提升为全局禁令。历史脚本保留原意与运行条件；如脱敏或泛化导致内容变化，标注“改写版未测试”，不要沿用原版验证结论。

## 来源可信度

对话可能已丢失前半段；明确写“可见材料不足”。消息无编号时用日期、主题和短释义定位，不伪造精确行号。私人材料不为补来源而发布到公网。全文或附件只在用户单独要求且适用时保存；大量代码优先引用真实项目文件与版本。
