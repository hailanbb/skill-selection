# 抖音图文笔记到 Obsidian

目标是生成一篇可直接阅读和复习的 Markdown 笔记，并把少量真正解释内容的关键画面嵌在相关段落中。取证思路参考 Rimagination/dy-note，但这个技能只发布最终笔记与关键图片；转写、音频、视频和候选帧都属于临时材料。

## 首次运行门槛

在处理视频前运行：

```powershell
python scripts/configure.py --status
```

如果返回 `configured: false`，只向用户询问一次以下两个绝对路径，然后等待回答：

1. Obsidian 中保存 Markdown 笔记的目录。
2. Obsidian 中保存笔记图片的目录。

取得路径后运行：

```powershell
python scripts/configure.py --note-dir "<笔记目录>" --image-dir "<图片目录>" --create-dirs
```

两个目录必须位于同一个含 `.obsidian` 的库中。配置有效后不重复询问；路径失效或用户要求换库时才重新配置。不要在首次配置前下载视频或运行转写。

## 工作流

1. 创建隔离的临时运行目录，并把本次下载、音频、转写和候选帧全部放进去：

```powershell
python scripts/run_workspace.py create
```

2. 取得来源 URL、作者、发布时间、标题/简介和可用文本证据。已有本地视频、字幕或转写时优先复用。需要从链接取证时，遵循 [取证与关键帧流程](references/workflow.md)。
3. 需要精确理解时，可在临时目录中复用本机 `dy-note` 的字幕/本地 ASR 能力。转写只是写笔记的证据，不是交付物，也不要整段复制到笔记。
4. 从视频抽取候选帧，结合内容段落逐张查看，选择通常 3–8 张非重复、能解释概念/步骤/对比/结果的画面。命令和选择标准见 [取证与关键帧流程](references/workflow.md)。
5. 按 [笔记格式](references/note-format.md) 写一个仅含正文的 UTF-8 Markdown 草稿。在画面应出现的位置放 `{{image:1|说明}}` 这类占位符。
6. 发布草稿。脚本会生成 YAML 属性、智能清理笔记文件名、把图片转为归档风格的哈希文件名、生成 Obsidian 库内链接并原子写入：

```powershell
python scripts/publish_note.py --draft "<正文草稿.md>" --title "<自然标题>" --source-url "<抖音 URL>" --author "<作者>" --publish-time "<发布时间>" --images "<关键帧1>" "<关键帧2>"
```

7. 对最终文件运行：

```powershell
python scripts/validate_note.py "<最终笔记.md>"
```

8. 无论成功、失败或中断，都在最后清理本次临时目录：

```powershell
python scripts/run_workspace.py cleanup --path "<本次临时目录>"
```

只有该脚本创建且带有匹配标记的目录可以清理。不要删除用户提供的原始本地视频，也不要清理 Obsidian 中已发布的笔记和图片。

## 硬性输出要求

- 最终仅保留一篇 `.md` 笔记及其被引用的关键图片；不要把视频、音频、候选帧、SRT/VTT、ASR JSON、时间轴或原始转写复制进 Obsidian。
- 不写“完整逐字稿”“全文转录”“可迁移自检清单”“实践清单”“自测题”及同类章节。
- 笔记必须是提炼后的知识视图：保留核心观点、推理/步骤、重要例子、适用边界和来源；短视频不要硬扩写成长文。
- 画面必须服务于相邻内容，不用装饰帧、重复帧、黑屏、纯片头、模糊过渡帧或仅展示无关人物的帧。
- 视觉结论必须由所选画面支持；ASR 无法证明画面文字、商品价格、动作细节或镜头顺序。
- 不读取、复制或记录 Cookie、token、签名视频 URL 等敏感数据。只使用用户已授权的浏览器会话或用户提供的本地材料。
- 文件使用 UTF-8 无 BOM。图片链接使用库根目录相对的 Obsidian wiki 嵌入格式。

## 命名与属性

- 展示标题用自然、准确、便于检索的中文，避免原标题中的营销前后缀和无意义编号。
- 笔记文件名与图片目录名使用清理后的短标题：保留中文、字母、数字、连字符和下划线，去除空白、标点及 Windows 非法字符；同名来源自动加短哈希避免覆盖。
- 图片统一缩放为宽度不超过 640 像素的 JPEG，并以 `<32位内容哈希>_640.jpg` 命名；无法转换时使用 `<32位内容哈希>_0.<原扩展名>`。
- YAML 属性固定参考用户样例：`title`、`category`、`url`、`origin`、`cover`、`author`、`publishTime`、`createTime`。

## 失败处理

- 没有可用文本且画面也无法读取：说明缺少什么证据，不生成猜测性笔记。
- 无法确认视觉内容：减少图片和视觉描述，不能用标题/简介替代画面证据。
- 发布校验失败：保留 Obsidian 原文件不变，修正临时草稿后重新发布；不要以覆盖现有笔记作为修复手段。
- `ffmpeg`、浏览器取证或 ASR 依赖缺失时，简短说明影响；安装依赖前按宿主 Agent 的授权规则处理。
