# 香港活動客戶分配

按「先讀取、再選類型、先預覽、確認後製檔」的固定流程執行。不得跳過使用者確認直接生成最終 Excel。

## 固定業務規則

- 使用繁體中文製作所有面向香港的內容。
- 按銷售名單中的實際列名人數計算小組容量；不自行推測出勤率。
- 將診所類客戶的工作量權重設為 `1.5`，其他客戶類型設為 `1.0`。
- 使用步行距離，不得用駕車距離替代。
- 已獲准僅向第三方地圖服務傳送地址或座標；不得傳送客戶名稱、電話、客戶類型、銷售姓名或小組資料。
- 客戶具備客戶類型、客戶名稱及有效地址即可進入距離計算與分配；電話缺失、電話為明顯佔位值，以及「已交流」「有意向」等來源狀態只作提示，不得阻止分配。
- 暫不自行套用指定小組或禁止分配等鎖定規則；若來源檔包含這類欄位，保留為提示並在預覽中說明，除非使用者另有明確指示。
- 優先順序：人均加權工作量公平 > 地理集中 > 客戶類型均衡 > 路線順序優化。
- Google Routes 的步行路線可能缺少部分行人道或步行路徑；在預覽及 Excel 中保留此提示。
- 預設只分配實際步行距離不超過 `4.00 KM` 的客戶；超過者不得分配，須完整列入 `超4KM客戶` 工作表。使用者明確指定其他上限時，以使用者要求為準。

## 第一步：只收集必要輸入

首次觸發時，先詢問以下資訊，不要立即詢問需要分配的客戶類型：

1. 客戶資料檔案的完整路徑。
2. 銷售團隊分組檔案的完整路徑。
3. 活動場地名稱及完整地址。
4. 最終 Excel 的保存目錄；未提供時使用與客戶資料相同的目錄。

接受 `.xlsx`、`.xls`、`.csv`、`.tsv`。路徑不存在、無法讀取或格式不受支援時，明確指出問題並請使用者修正，不得猜測資料。

## 第二步：分析來源檔

使用可用的 spreadsheet 工具讀取來源檔，遵循 [輸入欄位規則](references/input-contract.md)。

完成以下處理：

1. 識別最可能的表頭與資料工作表。
2. 正規化全形／半形空格、電話號碼及繁簡體欄位別名，但保留原始客戶名稱與地址供輸出。
3. 以「有效正規化電話 + 正規化地址」為主要重複判斷；缺電話或電話為明顯佔位值時，改用「客戶名稱 + 地址」。不要自動刪除疑似重複資料。
4. 缺少客戶類型、名稱或有效地址的資料列不參與分配並列入待核實。缺電話或電話為明顯佔位值不阻止分配，但須保留缺失提示；小組空白姓名不計入人數。
5. 統計每個小組的成員姓名與名單人數。
6. 列出識別到的所有客戶類型、原始數量、可定位數量及異常數量。

只在完成上述分析後詢問：「本次需要分配哪些客戶類型？」等待使用者回答。

## 第三步：計算步行距離

僅處理使用者選定的客戶類型。

優先使用現有、已授權且支援 `WALK` 模式的地圖工具。若沒有可用工具，使用 [google-walking-routes.mjs](scripts/google-walking-routes.mjs)，並從環境變數 `GOOGLE_MAPS_API_KEY` 讀取憑證；不得在對話、命令列回顯或輸出檔中顯示憑證。

地圖處理要求：

- 向地圖服務只提交場地地址、客戶地址或其座標。
- 將香港設為地區偏好，輸出公里並保留兩位小數。
- 記錄定位失敗、候選地址歧義、路線不可達及服務錯誤。
- 不得把直線距離偽裝成步行距離。若無法取得步行距離，將客戶放入待核實資料並暫不分配，除非使用者另行授權估算。
- 地圖臨時資料只保留至本輪工作完成；不得把姓名或電話寫入地圖快取。

## 第四步：分配客戶

按照 [分配方法](references/allocation-method.md) 準備標準 JSON，再執行：

```powershell
node scripts/allocation-engine.mjs input.json plan.json
```

核心輸入要求：

- 每個小組包含小組名稱與完整成員名單。
- 每個客戶包含唯一序號、客戶類型、名稱、地址、步行距離及定位座標；電話可為空白。
- 診所類型由正規化後包含「診所」「诊所」或 `clinic` 判斷，權重為 `1.5`。
- 非診所類型權重為 `1.0`。

若有小組人數為零、全部客戶均無法定位、沒有選中任何客戶類型或分配數量為零，停止並說明原因。

## 第五步：提交預覽並等待確認

在聊天中先展示：

- 每個小組的成員姓名及名單人數。
- 客戶總數、診所數量、其他類型數量。
- 各小組客戶總數、加權工作量、每人加權工作量。
- 各小組每種客戶類型的數量。
- 各小組平均及最遠步行距離。
- 無法定位、缺失欄位及疑似重複的客戶數量。
- 最高與最低「每人加權工作量」差異，以及無法完全均衡的原因。

明確詢問使用者是否確認此方案。未收到肯定確認前，只能調整方案，不得生成最終 Excel。

## 第六步：確認後生成 Excel

收到確認後，使用 spreadsheet 工具或 [build-workbook.mjs](scripts/build-workbook.mjs) 生成：

`場地名稱+銷售團隊客戶分工.xlsx`

建立五個工作表：

1. `分配總覽`：場地資料、計算口徑、小組人數、客戶數、加權工作量、人均加權工作量、各類型數量及距離指標。
2. `客戶分工`：序號、歸屬小組、客戶類型、客戶名稱、客戶地址、電話號碼、距離活動現場的距離（KM）、工作量權重。
3. `小組路線建議`：每個小組只建立一列總結，不逐客戶填寫路線說明。欄位至少包含小組、成員、客戶數、平均及最遠步行距離、建議起步區域／首站，以及整組路線規劃總結。總結應說明由活動場地出發、如何按街區／樓宇聚集分段、遠端客戶的處理次序及現場核實提示；沒有完整客戶間步行矩陣時必須標明為地理聚集建議，不得聲稱是最短路線。
4. `超4KM客戶`：列出序號、客戶類型、客戶名稱、客戶地址、電話、實際步行距離及不分配原因；所有距離必須大於本次上限，且不得與 `客戶分工` 重複。
5. `待核實資料`：問題類型、原始序號、客戶類型、客戶名稱、地址、電話及處理建議。缺電話但已分配的客戶可在此保留補充聯絡資料提示，不代表未分配。

格式要求：

- 全工作簿使用 `Microsoft YaHei`，同時設定西文字體與東亞字體。
- 所有表格儲存格水平、垂直置中；長文字自動換行。
- 使用克制、專業的深藍與淺藍配色，隱藏網格線。
- 設定篩選、凍結表頭、合理列寬與行高。
- 距離格式為 `0.00`，數量為整數，加權工作量為 `0.0`。
- `分配總覽` 的衍生指標優先使用可稽核公式引用 `客戶分工`。

生成後必須檢查：

1. 五個工作表均存在且沒有空白預設工作表。
2. 客戶分工總數與已分配客戶數一致，沒有重複唯一序號。
3. `小組路線建議` 的資料列數與小組數一致，每個小組只有一列總結。
4. `超4KM客戶` 全部超過本次距離上限，且與已分配客戶沒有重複或遺漏。
5. 公式無 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?` 或意外的 `#N/A`。
6. 渲染並逐頁檢查五個工作表，確保標題、欄位及長地址沒有被裁切。
7. 檔名已移除 Windows 不允許的字元，但保留可識別的場地名稱。
8. 交付後刪除預覽圖、標準 JSON、地圖快取及檢查記錄，只保留使用者的來源檔與最終 `.xlsx`。
