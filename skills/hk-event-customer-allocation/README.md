# 香港活动客户均衡分配 Skill

`hk-event-customer-allocation` 用于香港商场、写字楼、广场等公益义诊活动的线下拓客分工。它读取活动附近客户资料与销售团队分组，综合小组人数、客户类型、工作量和步行距离生成相对均衡的分配方案；只有在使用者确认方案后，才输出正式 Excel。

## 适用场景

- 公益义诊、健康咨询或推广活动开始前的客户扫街分工。
- 活动进行期间，根据附近商户、诊所、药房等名单安排销售小组拜访。
- 销售小组人数不同，需要按实际名单人数公平分配客户。
- 希望兼顾客户类型、步行距离和路线集中度，降低跨区往返。
- 需要生成可直接发给销售团队的繁體中文 Excel 分工表。

## 核心特点

- **按人数分配**：以团队文件中的名单人数计算各组容量，不推测出勤率。
- **诊所提高权重**：诊所类客户工作量为 `1.5`，其他类型为 `1.0`，即诊所比普通客户高 50%。
- **使用步行距离**：不以驾车距离或直线距离冒充步行距离。
- **名称地址即可分配**：选定类型的客户只要有名称和有效地址即可进入距离计算与分配；缺电话、占位电话及来源状态仅作提示。
- **4KM 分流**：默认只分配实际步行距离不超过 `4.00 KM` 的客户，超过者完整列入“超4KM客戶”。
- **多目标均衡**：优先平衡每人加权工作量，同时兼顾地理集中、客户类型比例和客户数量。
- **先确认再制表**：先展示每组人数、客户数量、类型构成、距离指标和均衡差异；收到明确确认后才生成 Excel。
- **隐私最小化**：地图计算仅提交地址或坐标，不提交客户名称、电话、客户类型、销售姓名或小组资料。
- **异常可追踪**：疑似重复、缺少字段、无法定位或步行路线不可达的记录进入“待核實資料”，不会静默删除。
- **结果可重复**：相同输入与配置会得到相同分配结果，方便审计和复核。

## 固定工作流程

### 1. 收集文件路径与活动资料

Skill 首先询问：

1. 客户资料文件的完整路径。
2. 销售团队分组文件的完整路径。
3. 活动场地名称及完整地址。
4. 最终 Excel 保存目录；未提供时默认使用客户资料所在目录。

支持 `.xlsx`、`.xls`、`.csv`、`.tsv`。如果文件不存在、无法读取或格式不支持，Skill 会停止并要求修正，不会猜测数据。

### 2. 分析数据并识别客户类型

Skill 自动识别常见字段别名，检查缺失值、疑似重复和成员名单，然后先展示：

- 每个销售小组的成员与名单人数。
- 识别到的所有客户类型。
- 各类型原始数量、可定位数量与异常数量。
- 缺失字段、重复客户和重复成员统计。

随后询问本次需要分配哪些客户类型。此时不会调用地图服务，也不会生成 Excel。

### 3. 计算步行距离

收到客户类型选择后，Skill 使用支持 `WALK` 模式的地图服务计算活动场地到客户的步行距离。若配置了完整步行距离矩阵，还会用于组内路线排序。

如果无法获得真正的步行距离，对应客户会进入待核实清单。除非使用者另行授权估算，否则不会以直线距离替代。

### 4. 生成分配预览

分配预览至少包括：

- 小组成员与名单人数。
- 各组客户总数。
- 各组加权工作量及人均加权工作量。
- 各组每种客户类型的数量。
- 平均步行距离与最远步行距离。
- 最高和最低人均加权工作量差异。
- 无法定位、缺失字段、疑似重复或未分配客户数量。
- 无法完全均衡时的原因。

Skill 会明确等待确认。使用者可以要求重新调整；只有明确回复确认后，才进入文件制作。

### 5. 生成 Excel

输出文件名：

```text
场地名称+销售团队客户分工.xlsx
```

工作簿包含五个页签：

| 页签 | 内容 |
|---|---|
| `分配總覽` | 场地资料、计算口径、小组人数、客户数量、加权工作量、人均工作量、类型构成及距离指标 |
| `客戶分工` | 序号、归属小组、客户类型、客户名称、客户地址、电话号码、距离活动现场的距离（KM）、工作量权重 |
| `小組路線建議` | 每个小组一条整体路线规划总结，包含首站、起步区域、距离指标及分段建议，不逐客户重复路线说明 |
| `超4KM客戶` | 实际步行距离超过本次上限、因此不分配给销售小组的客户及原因 |
| `待核實資料` | 疑似重复、字段缺失、定位失败、路线不可达等问题及处理建议 |

Excel 使用繁體中文、微软雅黑、专业蓝色配色、居中对齐、自动换行、筛选及冻结窗格，并对五个页签进行渲染检查。

## 分配算法

### 客户权重

| 客户类型 | 工作量权重 |
|---|---:|
| 类型名称包含“诊所”“診所”或 `clinic` | 1.5 |
| 其他类型 | 1.0 |

医院、药房、中医师公会等不会仅因医疗属性被自动视为诊所。

### 人数容量

假设小组人数为 `H_g`，所有小组总人数为 `H`：

- 目标客户数量 = 全部客户数 × `H_g / H`
- 目标加权工作量 = 全部加权工作量 × `H_g / H`
- 某客户类型目标数量 = 该类型总数 × `H_g / H`

### 综合评分

默认评分权重如下：

| 目标 | 占比 | 作用 |
|---|---:|---|
| 人均加权工作量偏差 | 45% | 优先保证不同人数小组的实际负担公平 |
| 人均客户数量偏差 | 10% | 防止客户数量明显失衡 |
| 地理分散程度 | 25% | 尽量把相近客户分给同一小组 |
| 客户类型偏差 | 20% | 尽量让各组获得相对均衡的客户类型 |

诊所优先分配，同权重时优先处理距离较远且数量较少的类型，再执行有限次数的再平衡。客户不可切分、诊所数量不足或地理位置冲突时允许存在小幅差异，但必须在预览中说明。

## 输入文件格式

### 客户资料

必要字段：

| 标准字段 | 常见别名 |
|---|---|
| 客户类型 | 客户类别、类型、类别、行业、type |
| 客户名称 | 名称、商户名称、公司名称、机构名称、name |
| 客户地址 | 地址、详细地址、营业地址、address |
| 电话号码 | 电话、联系电话、手机、phone、tel |

CSV 示例：

```csv
客户类型,客户名称,客户地址,电话号码
中医诊所,仁心中医诊所,香港中环皇后大道中1号,21230001
药房,康健药房,香港中环德辅道中20号,21230002
```

电话号码按文本处理，以保留前导零、`+852` 与分机。地址中的楼层、室号和铺号不会被擅自改写。

### 销售团队分组

支持两种结构。

逐行格式：

```csv
小组,成员姓名
第一组,陈一
第一组,李二
第二组,王三
```

分栏格式：每列表头为小组名，表头下每个非空单元格为一名成员。

空白姓名不计入人数；同组完全相同的姓名只计一次并提示；跨组同名人员保留并提示核实。

## 地图服务配置

Skill 优先使用运行环境中现有且支持步行模式的地图工具。如果没有，可使用附带的 Google Maps 脚本。

需要启用：

- Google Geocoding API
- Google Routes API

将 API Key 安全配置为环境变量：

```powershell
$env:GOOGLE_MAPS_API_KEY="你的密钥"
```

不要把密钥写进 `SKILL.md`、README、源代码、客户资料或命令输出，也不要提交到 GitHub。

获取场地至客户的步行距离：

```powershell
node scripts/google-walking-routes.mjs input.json geocoded.json
```

同时计算客户之间的步行距离矩阵，用于更精细的路线排序：

```powershell
node scripts/google-walking-routes.mjs input.json geocoded.json --full-matrix
```

完整矩阵会产生更多地图请求和费用；客户数量较多时应先确认配额与成本。

Google 的 `WALK` 路线可能缺少部分人行道或步行路径，最终文件会提示销售人员外勤前按现场情况核实。

## 脚本说明

| 文件 | 用途 |
|---|---|
| `scripts/google-walking-routes.mjs` | 地址定位、场地至客户步行距离及可选的完整步行矩阵 |
| `scripts/allocation-engine.mjs` | 确定性加权分配、再平衡和路线排序 |
| `scripts/build-workbook.mjs` | 生成、格式化并检查四页签 Excel |
| `tests/allocation-engine.test.mjs` | 验证诊所权重、结果唯一性、可重复性和无步行距离时的安全停止 |

分配引擎：

```powershell
node scripts/allocation-engine.mjs input.json plan.json
```

Excel 构建器：

```powershell
node scripts/build-workbook.mjs plan.json 输出目录 [预览目录]
```

这些底层命令主要供 Agent 或开发调试使用。日常使用时直接触发 Skill 即可，不需要手动准备内部 JSON。

## 隐私与数据处理

- 仅地址或坐标可发送给第三方地图服务。
- 客户名称、电话、客户类型、销售姓名和小组信息不得发送给地图服务。
- 地图临时数据只保留到当前工作完成。
- 最终交付后删除预览图、内部 JSON、地图缓存及检查记录，只保留使用者源文件与最终 Excel。
- 疑似重复或无法定位的客户不静默删除，全部进入待核实清单。

## 常见问题

### 为什么不能直接使用直线距离？

香港街区常受行人天桥、商场出入口、道路阻隔和坡度影响，直线距离可能与实际步行路线差异很大。因此没有真实步行距离时，Skill 会停止对应记录的自动分配。

### 为什么客户数量不是完全按人数比例？

客户不可切分，诊所权重更高，而且地理集中度与类型均衡也会影响结果。应以“每人加权工作量”作为主要公平指标，而不是只看客户个数。

### 为什么部分小组没有某一种客户？

如果该类型客户数量少于小组数，无法保证每组都有。Skill 会按人数比例和综合工作量分配，并在预览中解释差异。

### 地图定位失败怎么办？

补充香港地区、街道、楼层、室号或商场铺号后重新计算。无法确认的记录会保留在“待核實資料”，不会被删除。

### 是否支持指定客户给固定小组？

当前版本暂不应用指定小组、禁止分配或已跟进客户等锁定规则。来源文件若包含这些字段，只会列入待核实资料；后续可按业务需要扩展。
