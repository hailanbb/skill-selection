# 輸入欄位規則

## 客戶資料

必要欄位：

| 標準欄位 | 常見別名 | 規則 |
|---|---|---|
| 客戶類型 | 客戶類別、類型、類別、行业、行業、type | 缺失時列入待核實，不參與分配 |
| 客戶名稱 | 名稱、商戶名稱、公司名稱、機構名稱、name | 保留原文 |
| 客戶地址 | 地址、詳細地址、營業地址、address | 缺失時列入待核實，不傳送地圖服務 |
| 電話號碼 | 電話、聯絡電話、手機、phone、tel | 以文字處理，保留前導零及分機 |

可選欄位：原始序號、備註、區域、緯度、經度。現成座標仍須用步行路線服務計算距離。

## 銷售團隊資料

支援兩種常見版式：

1. 逐列格式：每列包含「小組」與「成員姓名」。
2. 分欄格式：每欄表頭是小組名稱，欄下每個非空儲存格是一名成員。

常見小組別名：歸屬小組、小組、組別、團隊、team、group。

常見成員別名：成員、姓名、銷售、業務員、member、name。

空白姓名不計入人數；同一小組內完全相同的姓名只計一次，但必須在預覽中提示疑似重複。跨小組同名人員保留並提示核實，不自行刪除。

## 正規化與重複判斷

- 去除首尾空格，將連續空格合併為一個。
- 比對電話時移除空格、括號及連字符，但輸出保留原電話。
- 香港電話若只有八位數，不自行補國碼；已有 `+852` 時保留。
- 地址比對時統一空格及常見標點，不擅自改寫樓層、室號或商場舖號。
- 主要重複鍵：正規化電話 + 正規化地址。
- 電話缺失時的備用鍵：正規化客戶名稱 + 正規化地址。
- 疑似重複資料不得靜默刪除；保留一列參與預覽，其餘列入待核實，並向使用者說明處理方式。

## 標準 JSON

分配引擎接受以下核心結構：

```json
{
  "venue": {"name": "場地", "address": "完整地址", "lat": 22.3, "lng": 114.2},
  "teams": [{"name": "A組", "members": ["甲", "乙"]}],
  "customers": [{
    "id": "1",
    "type": "診所",
    "name": "客戶名稱",
    "address": "客戶地址",
    "phone": "12345678",
    "distance_km": 0.85,
    "lat": 22.31,
    "lng": 114.21
  }],
  "walking_matrix": {"venue|1": 0.85, "1|venue": 0.85},
  "issues": []
}
```

`walking_matrix` 的鍵為 `起點ID|終點ID`，值為步行公里數。沒有客戶間矩陣時，路線順序只可標記為地理聚集建議，不得聲稱是最短步行路線。
