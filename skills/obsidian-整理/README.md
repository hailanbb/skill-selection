# Obsidian 自动整理与归档技能 (obsidian-整理)

> 🤖 为 Obsidian 用户打造的 AI 驱动笔记整理自动化技能。一键完成笔记的**语义分析、元数据生成、智能分类、重命名与归档**。

---

## ✨ 核心能力

| 能力 | 说明 |
|------|------|
| **语义分析** | AI 深度阅读笔记正文，提取摘要、标签、关键观点、知识图谱概念 |
| **智能分类** | 基于可自定义的分类体系，自动判定一级分类（文件夹）与二级分类（属性） |
| **AI 重命名** | 将冗长、乱码的原始文件名精炼为 10-25 字的高可读性标题 |
| **双重归档** | 加工后笔记归入分类文件夹 + 原始笔记备份到已整理文件夹 |
| **质量评分** | 对每篇笔记的信息密度、论证深度、原创性进行 1-5 分评估 |
| **自动自检** | 写入后自动审计 YAML 语法、Aliases、分类合规性，发现问题立即修复 |

---

## 📦 技能结构

```
obsidian-整理/
├── SKILL.md                    # 技能核心指令
├── README.md                   # 本文件
└── references/
    └── obsidian_note_categories_template.md  # 默认分类模板
```

## 🛠️ 第一阶段：首次初始化配置 (Onboarding)

首次触发时，AI 代理会依次询问以下配置参数（一次一问）：

| # | 配置项 | 示例 |
|---|--------|------|
| 1 | Obsidian 库本地路径 | `D:\MyVault` |
| 2 | 待整理文件夹名称（支持多个，逗号分隔） | `01 待阅收件箱, 02 Clippings` |
| 3 | 原笔记归档目标（处理完的原始文件备份目录） | `03 已整理` |
| 4 | 加工后笔记归档目标（AI 加工后的笔记归入目录） | `06 已归档` |

配置完成后自动执行以下检查：

- ✅ 确认 vault 路径存在
- ✅ 确认各文件夹存在，不存在则自动创建
- ✅ 检查 `obsidian_note_categories.md` 分类规范文件：
  - **不存在** → 从 `references/` 中自动复制默认模板到 vault 根目录
  - **已存在** → 读取用户自定义的分类体系（以用户版本为准）

> 💡 后续使用时无需重复配置，直接进入处理流程。

## 🚀 第二阶段：核心执行工作流

### 模式选择

- **批量模式**（默认）：用户说"整理笔记""整理收件箱"等泛指表达 → 扫描所有待整理文件夹，逐一处理
- **单篇模式**：用户指定了某篇笔记的路径或文件名 → 只处理该篇

---

### 步骤 1：读取笔记 (Scan & Load)

读取笔记的完整内容，包括已有的 frontmatter（如果有）和正文。

---

### 步骤 2：AI 语义分析与属性生成 (Semantic Analysis)

AI 深度阅读笔记内容，自动生成以下结构化 frontmatter 属性：

| 属性 | 生成规则 |
|------|---------|
| `author` | 从已有元数据提取，多个作者用 wiki link 格式（如 `[[作者A]], [[作者B]]`） |
| `description` | 中文总结核心内容，150 字以内，第三人称视角 |
| `source` | 从已有元数据提取原始 URL |
| `published` | 从已有元数据提取发布日期，格式 `YYYY-MM-DD` |
| `clipped` | 从已有元数据提取剪藏日期，格式 `YYYY-MM-DD` |
| `tags` | 分析文章主题，生成 3-5 个精准的中文标签词，不含 `#` 号 |
| `category` | 按分类规范判定的**二级分类**名称 |
| `key_points` | 提炼 3-5 个核心观点，每个用一句话概括 |
| `quality` | 评估内容质量（信息密度、论证深度、原创性），打分 1-5（5 最高） |
| `related_concepts` | 提取 3-5 个核心概念或知识领域关键词，用于构建知识图谱 |

**关键规则：**

- `author`、`source`、`published`、`clipped` 从原笔记已有 frontmatter 提取，**不存在则留空，绝不编造**
- 如果原笔记已有部分 AI 生成类属性，**保留已有值，只填充缺失的**——不覆盖用户手动填写过的值
- **YAML 语法极度严格**：所有以特殊字符开头（如反引号 `` ` ``、`@`、`%`、`*` 等）或内部包含冒号（`:`）、引号的字符串值，**必须用英文双引号 `" "` 包裹**，否则会导致 Obsidian 属性面板解析失败

---

### 步骤 3：分类定位 (Classification)

依据 vault 根目录的 `obsidian_note_categories.md` 中定义的分类体系进行匹配：

- **一级分类**：判定笔记的主要方向，并从文件中的 **「一级分类 → 文件夹名称映射」表** 获取**完整的归档文件夹名称**（含编号前缀，如 `1. 工具推荐`）

  > ⚠️ **绝对禁止省略编号前缀**！如果分类映射表中写的是 `1. 工具推荐`，归档文件夹必须创建为 `1. 工具推荐`，**而不是** `工具推荐`，否则会产生重复文件夹。

- **二级分类**：判定更细粒度的类别，写入 `category` 属性
- 每篇笔记**只归一个分类**，以主要意图为准，次要主题通过 `tags` 关联

**护栏机制：** 若笔记正文小于 50 字或完全无法归入现有体系，则**留在原位不动**，在报告中说明原因并提出建议。

---

### 步骤 4：文件名处理、重命名与归档 (Rename & Archive)

#### 4.1 文件名预处理（防乱码）
- **URL 解码**：如果原文件名被 URL 编码（如 `%E6%88%91...`），强制解码为可读字符
- **去除非法字符**：清除 `\ / : * ? " < > |` 等操作系统不合法字符

#### 4.2 AI 智能重命名
- 基于笔记正文与分类，生成**简洁明了、高度概括**的新文件名
- 控制在 **10-25 个字**，具有极高可读性
- 示例：`我想把国外视频一键翻成中文_然后发现了这个_GitHub_1_万_Star_的开源答案.md` → `GitHub万星视频一键翻译工具推荐.md`

#### 4.3 归档原件并添加 Aliases
- 将原始文件移动到原笔记归档文件夹（备份目录），文件名同步更新为新文件名
- **必须**在加工后笔记的 frontmatter 中新增 `aliases` 属性，记录原始文件名：
  ```yaml
  aliases: 
    - "我想把国外视频一键翻成中文_然后发现了这个_GitHub_1_万_Star_的开源答案"
  ```

#### 4.4 写入加工后笔记
- 在归档目录下，严格根据映射表中的**完整文件夹名称**（如 `1. 工具推荐`）创建子文件夹
- 将加工后的笔记文件（完整新 frontmatter + 原始正文）写入 `{加工归档目标}/{映射表中的文件夹名称}/{新文件名}.md`

---

### 步骤 5：整理后自检与修复 (Self-Audit)

写入完成后，AI **必须**立刻对输出的 Markdown 文件执行自我审计：

| 检查项 | 说明 |
|--------|------|
| YAML 语法合法性 | 所有以反引号、特殊标点开头的值是否已用双引号包裹 |
| Aliases 字段核对 | `aliases` 属性是否已正确写入并完整保留原始文件名 |
| 分类合规性 | `category` 值是否严格属于 `obsidian_note_categories.md` 定义的二级分类 |

> 如果在自检中发现任何格式错误或遗漏，必须立刻重写并覆盖该文件，直到完全满足规范。

---

### 步骤 6：无法归类的处理

满足以下任一条件的笔记**不会被移动**：
- 正文内容过短（少于 50 字）
- 内容不属于分类体系中的任何一级分类

保留在原始待整理文件夹中，并在报告中说明原因和具体建议。

## ⚠️ 注意事项

- 处理过程中**不修改笔记的正文内容**，只添加或更新 frontmatter 属性
- 文件操作前确认目标路径存在，不存在则自动创建
- 分类体系以用户 vault 中的 `obsidian_note_categories.md` 为准，每次运行时重新读取，确保用户修改后立即生效
- 遇到同名文件时，在文件名末尾追加时间戳后缀（如 `文件名_20240801`）避免覆盖
- URL 编码的文件名在步骤 4 第一步彻底解码，绝不将 `%` 编码文件名直接写入文件系统
- 所有 YAML 输出完全符合标准规范，特别是带反引号或标点符号的列表内容，必须用双引号包围
